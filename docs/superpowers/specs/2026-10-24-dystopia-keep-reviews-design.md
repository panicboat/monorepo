# Dystopia keep reviews after a party leaves design

## Context

#1690 は、プロフィールの削除や退会があってもカルテとクチコミを資産として残すことを求めている。ユーザーの言葉では「キャストが存在してるのにゲストが消えた場合にキャストへのクチコミが減るのは避けたい。逆もまた然り」。

カルテはすでにこの形になっている（`dystopia/docs/features/karte.md`）。作者のプロフィールが削除されても、アカウントが purge されても、カルテは残り、集計にも含まれる。そのため、作り直すのはクチコミだけになる。

今のクチコミの動き（`dystopia/docs/features/reviews.md`）:

- 書き手のゲストか対象のキャストが無効化中・退会中だと、クチコミは誰にも見えない。書き手が無効・退会中のときは平均には残る（`FilterVisibleReviews#own` が両当事者の有効を条件にしている）
- 書き手または対象のプロフィールが削除されると、`Review::UseCases::PurgeProfile` → `ReviewRepository#delete_by_profile` で、そのプロフィールが書いたクチコミも、そのプロフィールについて書かれたクチコミも消え、平均からも外れる
- 退会したアカウントの purge は、各プロフィールに対して削除と同じ処理（`Profile::UseCases::PurgeProfile` が各 slice の `purge_profile` を呼ぶ）を走らせる
- 作者の編集・評価・削除は、両当事者が有効なときだけできる（`LoadOwnReview`）

### Decisions taken before this spec

| 論点 | 決定 | 理由 |
|---|---|---|
| 守る対象 | 対象のキャストが有効なら、書き手のゲストがどうなってもクチコミの件数・平均は減らない | ユーザーの意図 |
| 書き手が無効化中・退会中のクチコミ | 名前を伏せて、今までどおり見える | ユーザーの判断。削除済みなら見えるのに、無効化だけだと見えない、という逆転を避ける |
| 対象のキャストが削除・purge されたクチコミ | 消さない。書いたゲストの「書いたクチコミ」一覧に、対象を伏せて出し続ける | ユーザーの判断。カルテと同じ形で、ゲストにとっても書いた記録が資産になる |
| 伏せた名前の表示 | 削除済み・無効・退会中を区別せず、同じ「（非表示ユーザー）」にする | ユーザーの判断。分ける理由がない |
| 「削除したプロフィール」の表示 | アプリ全体の共通表示（`ProfileName` / `profileDisplayName`）とカルテの「削除したプロフィールで記録」も「（非表示ユーザー）」にそろえる | ユーザーの判断（「削除したプロフィールで記録」は長い） |
| 設計書と plan | `docs/superpowers/` に置いて commit する | ユーザーの判断 |

## Goals

- プロフィールの削除・purge でクチコミを消さない（書き手側・対象側のどちらでも）
- 書き手のゲストが無効化・退会・削除されても、対象のキャストが有効なら、そのクチコミはキャストのクチコミ一覧・最近のクチコミ・個別表示に残り、平均・評価者数・件数にも残る
- 対象のキャストが無効化・退会・削除されても、書き手のゲストが有効なら、そのクチコミはゲストの「書いたクチコミ」一覧と個別表示に残る
- 有効でない当事者は、表示名・ユーザー名・アバター・プロフィールへのリンクを出さず「（非表示ユーザー）」と表示する
- 作者アカウントは、当事者の状態にかかわらず自分のクチコミを見て、編集・評価・削除できる（カルテの `LoadOwnKarte` と同じ）
- 相手のプロフィールが取れないときの表示を、アプリ全体で「（非表示ユーザー）」にそろえる
- 利用規約・プライバシーポリシー・プロフィール削除の確認文・docs を新しい動きに合わせる

## Non-goals

- カルテの残し方を変えること（すでに残る。変えるのは表示の文言だけ）
- 削除済みと無効・退会中を表示で区別すること
- 書き手が purge されたあとも、そのゲストへのブロックでクチコミを外し続けること（下の Visibility 参照）

## Anti-goals

- 有効でない当事者が誰かを推測できる情報（表示名・ユーザー名・アバター・プロフィールへのリンク）を出すこと

## Rules

### Terms

- **有効**: プロフィールが無効化されておらず、アカウントが退会中でなく、削除・purge されていない。`Profile::UseCases::ListVisibleProfileIds` が返す状態
- **到達できる**: 閲覧者がそのプロフィールの投稿を見られる（公開、または承認済みフォロー）。今の `filter_visible_posts` の判定

### What stays

クチコミの行は、プロフィールの削除でも purge でも消さない。消えるのは、作者が自分で消したとき（出来事を最後の 1 件まで消したときを含む）と、運営者が消したときだけになる。

| 出来事 | キャストのクチコミ一覧・最近のクチコミ | ゲストの「書いたクチコミ」一覧 | 平均・評価者数・件数 |
|---|---|---|---|
| 両当事者が有効 | 今どおり | 今どおり | 含む |
| 書き手のゲストが有効でない | 書き手を伏せて出る | ゲストのページがないので出ない | 含む |
| 対象のキャストが有効でない | キャストのページがないので出ない（最近のクチコミからも外れる） | 対象を伏せて出る | キャストが有効でないので 0（今どおり） |
| 両当事者が有効でない | 出ない | 出ない | 0 |

作者アカウント本人の「自分のクチコミ」一覧と件数には、当事者の状態にかかわらず、自分が書いたものがすべて出る。

### Visibility

| 場面 | 今 | 変更後 |
|---|---|---|
| 対象キャストのクチコミ一覧 | 両当事者が有効なものだけ。閲覧者が書き手とブロック関係にあれば外す | キャストが有効なら、書き手の状態にかかわらず出る。ブロックで外す動きは今どおり |
| ゲストの「書いたクチコミ」一覧 | 閲覧者がゲストに到達でき、対象キャストにも到達できるものだけ | ゲストが有効で閲覧者が到達できること（今どおり）。対象キャストが有効なら今どおり到達が必要。対象キャストが有効でなければ、対象を伏せて出る |
| 最近のクチコミ（ホーム） | 両当事者が有効で、対象に到達でき、どちらともブロック関係がないもの | 対象が有効で到達できること。どちらともブロック関係がないこと。書き手の状態は問わない |
| 個別表示（作者アカウントと対象キャスト本人） | 両当事者が有効なものだけ | 作者アカウントは常に開ける。対象キャスト本人は、自分が有効なら開ける |
| 個別表示（その他の閲覧者） | 最近のクチコミと同じ条件 | 閲覧者が見られるいずれかの一覧（キャストのクチコミ一覧、ゲストの「書いたクチコミ」一覧、最近のクチコミ）に出るなら開ける |
| 自分のクチコミ一覧と件数 | 両当事者が有効なものだけ | 作者アカウントが書いたものすべて |

- 対象キャスト本人がブロック関係を無視して自分へのクチコミを見られる、という今のルールは変えない。
- 書き手が purge されると、そのゲストに関わるブロックの行も消える。そのため、そのゲストをブロックしていた閲覧者にも、書き手を伏せたクチコミが見えるようになる。書き手が誰かは出ないので、これを受け入れる（設計上の判断）。

### Editing

- 編集・評価・削除は作者アカウントだけができる（今どおり）。
- 当事者の有効性は条件にしない（カルテの `LoadOwnKarte` と同じ）。対象キャストが無効・退会・削除されていても、作者は自分のクチコミを編集・削除できる。利用規約第11条の「書いたゲストは、自分のクチコミを削除できます」と一致させるため。

### Display

- `profileDisplayName(null)` と、表示名もユーザー名もない要約の表示を「（非表示ユーザー）」にする。`ProfileName` を使うすべての場所（投稿・コメント・DM・クチコミ・カルテなど）に効く。
- `ReviewCard` と `KarteCard` の、別プロフィールで書いたときの「削除したプロフィールで記録」を「（非表示ユーザー）として記録」にする。
- 有効でない当事者は、アバターを画像なし・頭文字「?」にし、プロフィールへのリンクを付けない（今は `profileDisplayName` の 1 文字目を頭文字にしているので、「（」が出てしまう）。対象側の表示（ユーザー名の「@...」の併記など）も同じく出さない。

### Legal text

| 場所 | 今 | 変更後の内容 |
|---|---|---|
| 利用規約 第6条第4項（`terms.ts` のキャストの複数プロフィールの段落） | 削除すると、書いたクチコミと書かれたクチコミも削除される | 削除しても、そのプロフィールで書いたクチコミと、そのプロフィールについて書かれたクチコミは残る。削除したプロフィールの表示名・ユーザー名・アバターは表示されない |
| 利用規約 第11条（クチコミ）の表示の項 | 内容と書いたゲストの表示名・ユーザー名・アバターが、対象キャストの投稿を見られる利用者に表示される | 加えて、書いたゲストまたは対象のキャストが無効化・退会・プロフィール削除をしてもクチコミは残ること、その場合その利用者の表示名・ユーザー名・アバターは表示されないこと、対象のキャストが表示されない場合は書いたゲストのプロフィールを見られる利用者に表示されること |
| 利用規約 第18条（退会）の第2項・第4項・最後の項 | クチコミはどちらが退会しても表示されなくなり、削除の対象。退会したゲストの評価は削除が済むまで集計に含む | クチコミは、どちらが退会しても残る（第2項の「除くもの」と第4項の「残るもの」に加える）。退会した利用者の表示名・ユーザー名・アバターは表示されない |
| プライバシーポリシー クチコミの段落（`privacy.ts` の退会・削除の節） | 同上 | 利用規約に合わせる。カルテの段落と同じ書き方にする |
| プライバシーポリシー 退会後の集計の箇条 | 削除が済むまで評価の集計に含む | 「キャストの評価の集計」を箇条から外す（削除が済んだ後も含まれるため）。クチコミの段落に「書いたゲストの評価は集計に残る」と書く |
| プライバシーポリシー 退会の段落 | 「次の2つの段落に定めるカルテと DM を除きます」 | クチコミも除くものと残るものに加える |
| プロフィール削除の確認文（`ProfileManager.tsx`） | 投稿・コメント・フォロー・クチコミが削除される | 投稿・コメント・フォローが削除される。クチコミは、このプロフィールで書いたものも、このプロフィールについて書かれたものも、名前を伏せて残る |

条番号・項番号は、今の `terms.ts` の並びと、`privacy.ts` からの参照（「利用規約第6条第4項」「利用規約第18条第2項および第7項」）から求めたもの。段落を足したり外したりして項番号がずれる場合は、番号で参照している箇所（両ファイルとそのテスト）もそろえる。

## Architecture

### Monolith (`review` slice)

- `Review::UseCases::PurgeProfile` と `ReviewRepository#delete_by_profile` を削除し、`Profile::UseCases::PurgeProfile` の呼び出し一覧から `::Review::Slice["use_cases.purge_profile"]` を外す。クチコミの行を消すのは作者の削除だけになる。
- `FilterVisibleReviews` を Visibility の表に合わせて作り直す。
  - キャストのクチコミ一覧（`call` で page owner がキャスト）: 書き手の有効性を問わない。ブロックは今どおり。
  - ゲストの「書いたクチコミ」一覧（`call` で page owner がゲスト）: 対象が有効なら到達を要求し、有効でなければ出す。
  - 最近のクチコミ（`recent`）: 対象の有効性と到達、両当事者とのブロックだけで判定する。
  - 自分のクチコミ（`own` を使っている `ListMyReviews`）: 作者アカウントのものすべて。
- `LoadOwnReview` から当事者の有効性の判定を外す。
- `GetReview`: 作者アカウントは常に開ける。対象キャスト本人は自分が有効なら開ける。その他は、キャストのクチコミ一覧・ゲストの「書いたクチコミ」一覧・最近のクチコミのいずれかの条件を満たせば開ける。
- `ListReviewsByTarget` と `ListReviewsByAuthor` の「page owner が有効でなければ空」は今どおり。
- `PresentReviews` は変えない。有効でない当事者の要約は取れず、`author` / `target` が `nil` で返る。

### Frontend

- `components/ui/profile-name.tsx`: `profileDisplayName` のフォールバック文言を「（非表示ユーザー）」に。
- `modules/review/components/ReviewCard.tsx`, `ReviewDetailSheet.tsx`, `modules/karte/components/KarteCard.tsx`: 「削除したプロフィールで記録」と、当事者がないときの頭文字・リンク・「@...」の併記を直す。
- 編集・削除の操作は `is_mine` で出しているはずなので、当事者が有効でないクチコミでも作者には出ることを確かめる。
- `modules/legal/content/terms.ts`, `privacy.ts`: 上の Legal text の表。
- `modules/profile/components/ProfileManager.tsx`: 削除の確認文。

### Docs

- `dystopia/docs/features/reviews.md`: Rules の閲覧・評価と平均・編集、Lifecycle、Interactions を新しい動きに。
- `dystopia/docs/features/profiles.md`: 削除で消えるものの一覧と、クチコミの Interactions。
- `dystopia/docs/features/karte.md`: 「削除したプロフィールで記録」の表示文言。
- `dystopia/docs/features/account.md`: purge で消えるもののうちクチコミの扱い。

### Data

- migration は不要。今ある行はそのまま新しいルールで見えるようになる。すでに消えたクチコミは戻らない。
- purge のあとも、クチコミの行には作者アカウントの ID（`author_account_id`）とプロフィールの ID が残る。カルテと同じ扱い。

## Testing

- `Profile::UseCases::PurgeProfile`（プロフィール削除と purge の経路）: ゲストを purge しても、キャストを purge しても、クチコミと出来事が残る
- `FilterVisibleReviews` / 各一覧の use case: Visibility の表の各行（書き手が無効・削除済み、対象が無効・削除済み、ブロック、到達）
- `ListReviewsByTarget`: 書き手のプロフィールを削除・purge したあとも、一覧と `rating_summary` の件数・平均が変わらない
- `ListReviewsByAuthor`: 対象のキャストを削除したあとも、ゲストの一覧に残る。対象が有効で鍵付き・未フォローなら今どおり出ない
- `GetReview` / `LoadOwnReview` / `ListMyReviews`: 当事者が有効でなくても、作者アカウントが開ける・編集できる・削除できる・数えられる
- frontend: `profileDisplayName(null)` が「（非表示ユーザー）」。`ReviewCard` と `KarteCard` で当事者がないときに「（非表示ユーザー）として記録」が出て、頭文字が「?」、リンクと「@...」が付かない。規約・プライバシーポリシーの既存テストの文言を更新する

## Calls made in this spec

設計の途中で私（Claude）が決めたもの。

- 書き手が purge されたあと、そのゲストをブロックしていた閲覧者にも、書き手を伏せたクチコミが見える（ブロックの行が消えるため）
- 作者の編集・評価・削除は、当事者の有効性を問わない（カルテと同じ。規約の「自分のクチコミを削除できます」と一致させる）
- 対象のキャストが有効でないクチコミは、最近のクチコミ（ホーム）には出さない（キャストを見つけるための一覧なので）
- その他の閲覧者の個別表示は、見られるいずれかの一覧に出るものに限る
