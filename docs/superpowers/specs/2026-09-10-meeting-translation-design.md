# Meeting Translation Design

| Date | Status | Scope |
| --- | --- | --- |
| 2026-09-10 | Design spec (implementation-ready) | Zoom 会議と並行して利用する、最大 3 人向けの日英双方向リアルタイム翻訳字幕 Web アプリ。参加者はログインせず、会議リンクから参加する。目的は会話の齟齬を減らし、通信・音声処理の一時的な失敗時にも意思疎通を継続できること。 |

## Goal

日本語話者と英語話者が Zoom を継続したまま、各自のブラウザで発話の原文と翻訳字幕を確認できるようにする。翻訳の確定結果は通常、発話終了から 3 秒以内に表示する。数値、日時、固有名詞、否定などの重要な発言を原文と照合し、必要に応じて再確認できるようにする。

## Non-Goals

- Zoom の音声・字幕・参加情報を API 経由で取得すること
- 翻訳音声を Zoom へ送ること
- 会議録、字幕、音声、利用者プロフィールを永続保存すること
- 4 人以上の会議や、日本語・英語以外の言語を扱うこと

## Decisions

| Item | Decision |
| --- | --- |
| Participants | 最大 3 人。各参加者が表示名を入力する。 |
| Entry | ログイン不要。作成者が会議リンクを共有し、参加者は表示名・発話言語・表示言語を設定して入室する。会議 ID と参加トークンは分離し、トークンは URL fragment に置く。 |
| Languages | 発話・表示言語は日本語または英語を個別選択する。 |
| Zoom integration | Zoom とは連携しない。各参加者が Zoom と翻訳アプリを別に開き、自分のマイクを翻訳アプリへ許可する。 |
| Speech recognition | Amazon Transcribe Streaming を参加者ごとに 1 ストリーム使用する。 |
| Translation | 確定した原文と会議中の短い文脈、用語集を Amazon Bedrock へ送り、翻訳する。 |
| Accuracy | 原文と訳文を常に照合できるようにし、未確定の認識結果を他参加者の訳文として表示しない。 |
| Clarification | 各発話に確認要求を付けられる。発話者には再説明依頼を自分の表示言語で表示する。 |
| Continuity | 退出後も残った参加者は会話を継続できる。再参加者には過去の字幕を再送しない。 |
| Fallback | 音声認識または翻訳が利用できない時は、手入力した文を翻訳して同じ字幕欄へ表示する。 |
| Consent | 入室前に、音声と字幕を外部 AI 処理へ送信することへの同意を必須にする。 |
| Retention | アプリケーションは字幕・音声を永続保存しない。最後の参加者が退出した時点で会議状態を破棄する。AWS 側のデータ保持設定は翻訳精度・可用性を優先して選択する。 |

## Architecture

既存の認証必須の SNS フロントエンドとは分離し、公開ページとリアルタイム処理を持つ `meeting-translation` サービスを追加する。ログイン不要の利用者導線と長時間の双方向接続を既存の認証・gRPC BFF に混在させないためである。

```text
Participant browsers
  │ microphone audio, room events
  ▼
Meeting Translation Service ──► Amazon Transcribe Streaming
  │                                  │ finalized source text
  │◄─────────────────────────────────┘
  │ contextual translation request
  ▼
Amazon Bedrock ──► finalized caption events ──► Participant browsers
```

ブラウザは `Meeting Translation Service` だけに接続する。AWS 認証情報と Bedrock 呼出権限をブラウザへ配布しない。サービスは Amazon Transcribe と Bedrock を呼び、参加者間のイベント配信、会議の接続状態、短期文脈を管理する。

## Components

### Meeting Entry

作成者は会議 ID と推測困難な参加トークンからなる会議リンクを発行する。参加トークンは URL fragment に置き、ブラウザが最初の WebSocket メッセージで送信する。HTTP リクエストとそのアクセスログへトークンを含めないためである。入室時に表示名、発話言語、表示言語、AI 処理への同意を受け付ける。会議作成 API にはレート制限を設け、未認証 URL の不正な利用によるコスト増加を抑える。

### Meeting View

会議画面はマイク開始・停止、接続状態、参加者一覧、字幕時系列、手入力欄を表示する。字幕イベントは発話者、原文、訳文、確定状態を持つ。表示言語と原文が同じ場合は原文を主表示にし、異なる場合は訳文を主表示にする。原文と訳文はどちらも展開して確認できる。

### Clarification Control

参加者は特定の字幕に確認要求を付けられる。サービスは対象発話と要求を会議内へ配信し、発話者には再説明を促す固定メッセージを表示する。確認要求は翻訳品質を推定する指標ではなく、参加者自身が意味を確認するための操作である。

### Realtime Coordinator

`Realtime Coordinator` は会議ごとの参加上限、接続・退出・再接続、字幕イベント、短期文脈を管理する。会議に参加者が残る間だけ状態を保持する。参加者が再接続すると以後の字幕を配信するが、過去の字幕は再送しない。最後の参加者が退出したら会議状態を破棄する。

### Speech Recognition Adapter

`Speech Recognition Adapter` は参加者ごとに Amazon Transcribe Streaming の接続を開始・停止する。ブラウザからの音声チャンクを Transcribe へ送信し、途中結果は発話者の原文プレビューにだけ返す。確定結果だけを翻訳アダプターへ渡す。

### Translation Adapter

`Translation Adapter` は Bedrock のモデル、リージョン、用語集を環境設定から受け取る。確定した原文、発話言語、対象言語、直近の確定発話を翻訳リクエストに含める。翻訳以外の回答を出力しないよう制約し、訳文を確定字幕イベントとして返す。

## Data Flow

1. 作成者が会議リンクを発行し、参加者は設定を完了して WebSocket 接続する。
2. 各ブラウザは自分のマイク音声を小さなチャンクで送信する。Zoom の混合音声は送信しない。
3. `Speech Recognition Adapter` は途中の原文プレビューを発話者へ返す。確定した原文だけを `Translation Adapter` へ送る。
4. `Translation Adapter` は短期文脈と用語集を使って Bedrock で翻訳し、確定字幕イベントを会議内へ配信する。
5. 各参加者は発話者・主表示の文・原文・確定状態を自分の表示言語で確認する。
6. 音声認識または翻訳が失敗した場合、接続状態と失敗理由を表示し、自動再接続を試みる。利用者は手入力欄から同じ字幕イベントを送信できる。

## Reliability

音声の送信、Transcribe のストリーム、Bedrock の翻訳、参加者との WebSocket 接続はすべて明示的に開始・停止する。参加者の退出、WebSocket の切断、ブラウザのページ非表示・終了で、その参加者の音声取得と Transcribe ストリームを停止する。サービスは再接続可能なエラーだけを指数バックオフで再試行し、再試行中であることを参加者へ表示する。

翻訳が失敗しても、確認済みの原文を隠さない。音声認識が失敗している場合は、手入力翻訳を会話継続手段として提供する。会議状態を保持するプロセスが再起動した場合は、再接続を促し、過去の字幕を復元しない。

## Security and Privacy

- 会議リンクの参加トークンは URL fragment に置く bearer credential として扱い、HTTP リクエスト、参照元 URL、ログへ出力しない。
- ブラウザは AWS 認証情報を持たず、サービスの実行ロールだけが AWS サービスを呼び出す。
- 音声、文字起こし、翻訳結果をアプリケーションのデータベース、オブジェクトストレージ、ログへ保存しない。
- 入室同意画面は、音声と字幕が Amazon Transcribe と Amazon Bedrock に送信されることを明示する。
- アプリケーションにおける字幕表示と会議内の短期文脈は、最後の参加者が退出した時点で破棄する。

## Success Criteria

- 3 人が同時接続し、日本語と英語の発話を各参加者の表示言語へ正しく配信できる。
- 通常のネットワーク条件では、発話終了から確定訳文の表示まで 3 秒以内を目標にする。
- 原文、訳文、発話者、途中・確定状態が正しい順序で画面へ表示される。
- 一人が退出または再接続しても、残った参加者は翻訳会話を継続できる。
- 最後の参加者が退出した時点で、アプリケーションの会議状態が破棄される。
- 音声認識または翻訳が失敗しても、手入力による翻訳会話を継続できる。
- 数値、日時、固有名詞、否定、依頼を含む発話は、原文照合と確認要求の操作によって人手で再確認できる。

## Testing

### Automated Tests

- 会議作成、参加、3 人上限、退出、再接続、最後の退出時の状態破棄を単体テストする。
- 字幕イベントの順序、発話者、発話言語、表示言語、途中・確定状態を単体テストする。
- Transcribe と Bedrock はテストダブルに置き換え、日本語・英語の発話、数値、日時、固有名詞、否定、依頼を含む評価文で翻訳リクエストと表示契約を検証する。
- 音声認識失敗、翻訳失敗、WebSocket 切断の各ケースで、状態表示、自動再接続、手入力翻訳を統合テストする。
- ブラウザへ AWS 認証情報を含む設定値が渡らないことを検証する。

### Manual Verification

- Zoom と 3 ブラウザを並行して開き、各参加者が Zoom と翻訳アプリで同じマイクを利用できることを確認する。
- 日英双方の実発話で、3 秒目標、原文・訳文の照合、確認要求、退出・再接続、手入力への切替を確認する。
- 数値、日時、固有名詞、否定、依頼を含む会話例について、参加者が原文と訳文の意味を確認する。

## Trade-offs

- Zoom API と連携せず参加者ごとのマイクを使うため、Zoom の混合音声による話者識別の誤りを避けられる。一方で、全参加者が翻訳アプリを開き、マイク利用を許可する必要がある。
- 途中の認識結果を翻訳しないため、字幕の確定まで短い待ち時間がある。一方で、不完全な文に基づく誤訳を全参加者へ共有しない。
- Bedrock に短期文脈を送るため、単文翻訳より自然な訳を期待できる。一方で、翻訳リクエストの遅延とコストは増える。
- WebSocket を持つ独立サービスを追加するため、デプロイ対象は増える。一方で、既存の認証 BFF とリアルタイム音声ストリームの寿命を分離できる。
