# Dystopia Post Quote Design

Issue: [#1886](https://github.com/panicboat/monorepo/issues/1886)

## Intent

話題の投稿に自分の意見を添えて、自分のフォロワーに届けられるようにする。
今はコメントするしかなく、返信欄に埋もれてフォロワーに届かない。
元の投稿を見に来た人が、引用された意見を辿れるようにもする。

## Goals

- 投稿を引用して、通常の投稿として作成できる。
- 引用投稿は通常の投稿と同じくフィード・検索・ハッシュタグ・いいね・コメントの対象になる。
- 元の投稿に引用数が出て、そこから引用の一覧を辿れる。
- 元の投稿者に、引用されたことが通知で届く。

## Non-goals

- 本文のないリポスト。
- コメント・返信の引用。
- ランキングへの引用数の反映。
- 引用枠の入れ子表示。

## Anti-goals

- 炎上しそうな投稿の晒し上げを助長する機能にしない。
- 見られないはずの投稿の中身を、引用を経由して見せない。
- 「フォロワーのみ」の投稿への意見だけが、中身を見られない人に届く状態を作らない。

## Decisions

### Who can quote what

引用できるのは、引用する人が今見られて、公開範囲が「全員」で、表示中の投稿だけ。
投稿者とのロールの組み合わせは問わない。

| 引用元 | 引用 |
| --- | --- |
| 「全員」公開で表示中の他人の投稿 | できる |
| 鍵付きプロフィールの「全員」公開の投稿 | できる |
| 自分の「全員」公開で表示中の投稿 | できる |
| 引用投稿 | できる |
| 予定のお知らせ投稿 | できる |
| 「フォロワーのみ」の投稿（自分の投稿も含む） | できない |
| ブロック関係（どちら向きでも）にある相手の投稿 | できない |
| 予約中または表示終了の投稿（自分の投稿も含む） | できない |
| コメントと返信 | できない |

- 鍵付きプロフィールの投稿を引用できるのは、鍵が投稿の閲覧に効かない仕様だから。
  - 鍵付きプロフィールの投稿画面の初期値は「フォロワーのみ」なので、「全員」は本人が選んだものと見なす。
- 投稿は作成後に編集できないので、引用元の本文と公開範囲は後から変わらない。
  - 例外はお知らせ投稿で、同じ行のまま予定の保存でひとことと終了時刻が更新される。
    - 引用枠には更新後の内容を出す。
    - 終了時刻が未来に延びれば、引用枠も再び見えるようになる。
  - お知らせ投稿が削除された後に作り直されても新しい行になり、既存の引用は付け替えない。
    - 既存の引用の枠は「この投稿は表示できません」のままで、新しいお知らせの引用数は 0 から始まる。
- 判定はサーバーでも行う。
  - 画面でボタンを隠すだけにしない。

### Quote post

引用投稿は、引用元を指す情報を持つ通常の投稿とする。

- 本文は必須で、通常の投稿と同じ検証を行う。
- 公開範囲・予約・表示終了・添付・ハッシュタグ・メンションは通常の投稿と同じ。
  - 「フォロワーのみ」の引用も作れることをユーザーが確認済み。
    - 元の投稿者がフォロワーでなければ、その引用は見えず、通知も届かない。
- 引用元は作成後に変えられない。
- 検索とハッシュタグは引用投稿自身の本文だけを対象とし、引用元の本文では当たらない。
- プロフィールの「メディア」タブは引用投稿自身の添付だけを対象とする。

### Quote frame

引用枠の中身は、見る人ごとに判定する。

- 見られるとき: 投稿者の名前（鍵マークを含む）、本文、画像・動画、投稿の時刻を小さく表示する。
  - 長い本文は数行で省略する。
  - お知らせ投稿では予定の表示も出す。
  - 押すと元の投稿の詳細を開く。
  - 引用元がさらに引用していても、枠の中に枠は出さない。
- 見られないとき: 枠に「この投稿は表示できません」と表示し、引用投稿の本文はそのまま残す。
  - 対象は、削除・表示終了・ブロック関係・投稿者の無効化・投稿者の削除・アカウントの退会など、投稿の閲覧判定で見えなくなるすべて。
  - 理由は出し分けない。

引用投稿は引用元の削除で消えない。

### Original post side

カードのリアクション列に、引用のアイコンと数字を出す。

- 並びは、いいね、引用のアイコンと数字、コメント、ブックマークの順にする。
  - ユーザーの指定による。
  - 自分の投稿のピン留めと削除は、ブックマークの後に並べる。
- アイコンは lucide-react の `Repeat2` を使う。
  - x.com のリポストと同じ形にするというユーザーの指定による。
- 文字のラベルは付けない。
- アイコンを押すと引用の作成画面が開き、1 回押すだけで投稿されることはない。
- 数字を押すと、投稿の詳細が引用タブで開く。
- アイコンと数字は別々に押せるようにし、それぞれ今のカードのボタンと同じ大きさを確保する。
- 引用できない投稿では、アイコンを無効の見た目にする。
  - 数字は押せる。
- 自分の予約中と表示終了の投稿でも同じにする。

投稿の詳細では、今のコメント欄をコメントと引用のタブに分ける。

- 既定はコメントのタブ。
- タブの見出しにそれぞれの件数を出す。
- 引用タブは閲覧者が見られる引用投稿を新しい順に並べる。
  - 順序とページングはフィードと同じく公開開始時刻の降順、同じ時刻は ID の降順、既定 20 件、上限 50 件とする。
- 引用タブの各行は通常の投稿カードとし、引用枠は出さない。
  - 元の投稿が同じ画面の上にあるため。

### Quote count

引用数は、閲覧者が引用タブで見られる件数と一致させる。

- 閲覧者とブロック関係（どちら向きでも）にある人の引用は数えない。
- 閲覧者が見られない「フォロワーのみ」の引用は数えない。
- 予約中・表示終了の引用は、本人以外には数えない。
- 無効化・退会中・削除済みの投稿者の引用は数えない。

コメント数・いいね数の規則（閲覧者がブロックした側だけ除く）とは異なる。
一覧と数を揃えることを優先したユーザーの判断による。

引用が多い投稿でも正確な件数を出し、上限表示（99+ など）や概数にはしない。
`filter_visible_posts` は取得済みの行を Ruby で絞る作りなので、全引用行をこれに通すと引用数に比例して重くなる。
件数は同じ条件を DB で集計するなど、行を読み込まない方法で求める。

### Notifications

通知の種類に「引用」を足す。

- 送り先は元の投稿の投稿者。
- 集約は既存の規則に従い、同じ受信者・種類「引用」・同じ元の投稿で 1 行にまとめる。
- 通知を押すと、元の投稿の詳細が引用タブで開く。
- 本文の抜粋は引用投稿の本文を使う。
- 送らない条件は、メンションの通知と揃える。
  - 自分の投稿を引用したとき。
  - 引用投稿の表示開始が未来のとき（表示開始後も送らない）。
  - 元の投稿者が引用投稿を見られないとき。
  - 受信者が発火者をブロックしているとき。
- プロフィールごとの通知設定に「引用」を足し、初期値は on とする。
  - 設定は既存の種類と同じく Web Push だけを制御する。
- 引用投稿の本文で元の投稿者をメンションしていれば、メンションと引用の両方が届く。

### Self defense

晒された人の手段は、元の投稿の削除とブロックとする。
引用から自分の投稿を外す操作と、引用を禁止する設定は作らない。

- ユーザーの判断による。
- ブロックすると、ブロックした人とされた人には引用枠が「この投稿は表示できません」になる。
  - 第三者には引用枠の中身が見え続ける。
- 元の投稿を削除すると、全員に対して引用枠が「この投稿は表示できません」になる。

## Constraints

- `dystopia/docs/features/posts.md` の閲覧判定を変えない。
  - 引用枠と引用一覧は `Social` の `filter_visible_posts` と同じ判定を通す。
- 今のカードのアイコンは lucide-react で揃っている。
  - frontend は `lucide-react` の `Repeat2` を追加の依存なしで使える。
- `dystopia/docs` の仕様を実装と同じ PR で更新する。
  - `posts.md`・`notifications.md`・`feed-and-ranking.md`（引用投稿の扱い）・`follows-and-blocks.md`（ブロックの影響表）・`data-model.md` が対象。
- デプロイは migrate → アプリ更新の順で行われるので、追加の migration は既存のアプリを壊さない形にする。
- `bin/codegen` と `pnpm proto:gen` は無関係な stub にも差分を出す。
  - 変更した package の stub だけ commit する。
- monolith の CI は rspec を回さないので、ローカルの rspec を必ず通す。

## Left to the builder

次は builder の判断でよい（すべて Claude の案で、ユーザーの判断ではない）。

- データの持ち方。
  - 案: `post.posts` に NULL 可の `quoted_post_id` を足し、削除で値を消さない。
  - 元の投稿を削除した後も「引用だった」ことが残る必要があるので、`ON DELETE SET NULL` は使えない。
- 引用数の取得方法。
  - 全カードで使うので、1 ページ 20 件で投稿ごとにクエリを発行しない形にする。
- 引用一覧の RPC と、詳細タブの URL の表し方。
- 作成画面の構成。
  - 既存の `PostComposer` と `PostComposerSheet` に、引用元の表示を足す想定。
- 「この投稿は表示できません」以外の細かい文言。

## Calls made by Claude

ユーザーが「良さそう」と確認した範囲に含まれるが、発案は Claude のもの。

- 引用できる投稿の条件の各項目。
- 引用数を閲覧者が見られる件数に揃えること。
- 引用枠の中身と省略。
- 引用投稿を通常の投稿と同じ機能にすること。
- ランキングに引用数を使わないこと。
- 通知の種類を足すこと。

ユーザーがまだ確認しておらず、Claude が決めたもの。

- 引用数は上限表示や概数にせず、正確な件数を出すこと。
- 引用できない投稿のアイコンを無効の見た目にし、数字は押せるままにすること。
- 引用タブの各行に引用枠を出さないこと。
- 詳細の既定のタブをコメントにすること。
- 通知を押すと引用タブが開くこと。
- 引用投稿の本文で元の投稿者をメンションすると、通知が 2 つ届くこと。
- お知らせ投稿の作り直しで既存の引用を付け替えないこと。
