# Dystopia timed posts design

## Context

投稿は作った瞬間から無期限に表示される。#1585 は、表示開始と表示終了の時刻を指定して、その期間だけ表示する投稿を求めている。指定しない投稿は今どおり無期限に表示する。

インフラには決まった時刻に処理を動かす仕組み（定期実行）がない。そのため、表示するかどうかは、投稿を読むたびに今の時刻と比べて決める。

### Decisions taken before this spec

| 論点 | 決定 | 理由 |
|---|---|---|
| 開始前の投稿 | 本人のプロフィールにだけ「予約」として出す。他人にはどこにも出さない | ユーザーの判断 |
| 終了後の投稿 | 本人以外にはどこにも出さない。本人のプロフィールには「表示終了」として残す | ユーザーの判断 |
| 予約投稿のメンション | 通知しない | ユーザーの判断。開始前に開けない投稿への通知を防ぐ。開始時刻に送るには定期実行の仕組みが要る |
| 投稿一覧の並び順 | タイムライン・プロフィール・検索・ハッシュタグを表示開始の時刻で並べる | ユーザーの判断。予約投稿は開始時刻に新着として一番上に来る。今の投稿は作成時刻＝開始時刻なので並びは変わらない |

## Goals

- 投稿に表示開始と表示終了の時刻を指定できる。指定しなければ今どおり（すぐ表示、無期限）
- 表示期間外の投稿は、本人以外にはどこにも出ない（タイムライン、プロフィール、投稿詳細、検索、ハッシュタグ、ランキング、ブックマーク、いいねの一覧）
- 本人はプロフィールで、予約中・表示終了の投稿を確かめられる
- タイムライン・プロフィール・検索・ハッシュタグの一覧は表示開始の時刻で並ぶ（いいね・ブックマークの一覧は、いいね・保存した時刻のまま）

## Non-goals

- 開始時刻のメンション通知（定期実行の仕組み）
- 他人向けに「〜まで表示」などの期限を出すこと
- 表示期間の一括変更

## Rules

### Terms

- **表示開始** `published_at`: 投稿が表示され始める時刻。指定しなければ作成時刻
- **表示終了** `expires_at`: 投稿が表示されなくなる時刻。指定しなければ無期限
- **表示中**: `published_at <= 今` かつ（`expires_at` がない、または `expires_at > 今`）

### Who sees what

| 投稿の状態 | 本人 | 他人 |
|---|---|---|
| 表示中 | 今どおり | 今どおり（鍵・フォロワーのみ・ブロックのルールもそのまま） |
| 予約中（開始前） | プロフィールに「予約」として出る。投稿詳細を開ける | どこにも出ない。投稿詳細は見つからない扱い |
| 表示終了 | プロフィールに「表示終了」として出る。投稿詳細を開ける | どこにも出ない。投稿詳細は見つからない扱い |

本人のタイムライン（全国・エリア・フォロー中・フォロワー）にも、表示中の投稿だけを出す。予約中・表示終了の投稿は、本人もプロフィールで確かめる。

### Saving

- 新しい投稿: 表示開始を指定しなければ今。指定するなら今より後
- 表示終了を指定するなら、表示開始より後で、かつ今より後
- 編集:
  - 表示開始は、予約中の投稿だけ変えられる（表示中・表示終了の投稿では変えない）
  - 表示終了は、いつでも変えられる。消せば無期限になる
- 予約で作った投稿（作成時に表示開始が今より後）は、メンションの通知を送らない。表示中で作った投稿は今どおり送る

## Architecture

### Database (`post.posts`)

- `published_at timestamptz NOT NULL DEFAULT now()`。migration で既存の行は `created_at` を入れる
- `expires_at timestamptz NULL`
- 制約: `expires_at IS NULL OR expires_at > published_at`
- 索引: `(published_at DESC, id DESC)`（タイムラインとプロフィールの並び）

### Monolith

- post repository:
  - タイムライン（`list_post_ids`）、プロフィールの一覧（`list_posts`）、検索、ハッシュタグ、ランキングの問い合わせに「表示中」の条件を足す。プロフィールの一覧は、本人が自分の一覧を見るときだけこの条件を外す
  - タイムライン・プロフィール・検索・ハッシュタグの並びとカーソルを `published_at` にする。ランキングの期間の絞り込みも `published_at` で行う
- social `FilterVisiblePosts`: 投稿が `published_at`・`expires_at` を持つとき、本人以外には表示中の投稿だけを通す（投稿詳細・ブックマーク・いいねの一覧・コメント・いいねの操作は、これを通るので同じルールになる）
- post の保存: 表示開始・終了を受け取り、上の Saving のルールで検証する（違反は INVALID_ARGUMENT）。予約で作った投稿ではメンションの通知を送らない
- presenter: `published_at`・`expires_at` を返す

### Proto (`post.v1`)

- `Post`: `string published_at = 13; string expires_at = 14;`（`created_at` と同じ文字列の形式。`expires_at` がなければ空）
- `SavePostRequest`: `string published_at = 6; string expires_at = 7;`（空は「指定なし」）

### Frontend

- 投稿画面: 「表示期間を指定」の切り替え。入れると「表示開始」「表示終了」の日時の入力を出す（空なら、すぐ・無期限）
- 投稿カード: 本人の予約中の投稿に「予約 M/D HH:mm から」、表示終了した投稿に「表示終了」の印。時刻の表示（〇分前）は表示開始の時刻を使う
- 編集: 予約中なら表示開始と表示終了、それ以外は表示終了だけを変えられる

## Testing

monolith（rspec）:

- 表示中・予約中・表示終了のそれぞれで、本人と他人に、タイムライン・プロフィール・投稿詳細・検索・ハッシュタグ・ランキング・ブックマーク・いいねの一覧の出し分け
- タイムライン・プロフィール・検索・ハッシュタグの並びが表示開始の時刻で、カーソルでページを送れる
- 保存の検証（開始が過去、終了が開始より前・過去、表示中の投稿の開始を変える）
- 予約で作った投稿はメンションを通知しない
- migration で既存の投稿の `published_at` が `created_at` になる

frontend（vitest、`tsc --noEmit`）:

- 投稿画面の表示期間の入力と、保存する値
- カードの「予約」「表示終了」の印（本人だけ）

ローカルの実機:

- 予約の投稿が、開始前は本人のプロフィールにだけ「予約」で出て、他人には出ない
- 終了時刻を過ぎた投稿が他人から消え、本人のプロフィールに「表示終了」で残る
