# Dystopia karte screens design

## Context

[Issue #1519](https://github.com/panicboat/monorepo/issues/1519)「カルテの体験を向上する」への対応の第 3 段。4 段の stack の位置づけは [design foundation の spec](2026-10-12-dystopia-design-foundation-design.md) を参照。

第 2 段（[karte lifecycle の spec](2026-10-16-dystopia-karte-lifecycle-design.md)）で、カルテは「1 回の予約〜接客後 = 1 カルテ」の形になり、既存の画面はその形で動く最小限の改修にとどめた。本段は [#1517](https://github.com/panicboat/monorepo/issues/1517) のモック（`dystopia_city_motion_ux_v2.html`）のカルテ画面に作り直す。目的は #1519 §11 のとおり、キャストがゲストから連絡を受けたときに平均評価ですぐ判断でき、少ない操作で記録できること。

### Decisions taken before this spec

| 論点 | 決定 | 理由 |
|---|---|---|
| 操作の置き場所 | カードは要約だけを出し、操作はすべて詳細シートに置く | モックの構成。一覧を読むときに操作が邪魔にならない |
| 作成者の操作 | 追記、出来事の編集・削除、記録中の星の変更、完了・再オープン、カルテの削除 | #1519 §8.2 の「追記・編集」。書き間違いを直す手段がないと、消して作り直すしかなくなる |
| 詳細シートの開き方 | 一覧ごとに「開いているカルテの id」を持ち、カードを押すと開く。操作のあとは、表示中のカルテの一覧と詳細をすべて取り直す | 第 1 段の `ComposeToSheet` と同じ形で、新しい仕組みを足さない。どの一覧で操作しても、他の一覧と平均評価が最新になる。URL で開くカルテ（intercepting route）は、リンク元がないので作らない |
| 自分のカルテの件数の欄 | `ListMyKartes` の応答に件数を足して出す | ページ単位の一覧からは正しい件数を数えられない |
| 自分のカルテとプロフィールの並び順 | 最後の動きの日時の新しい順 | カルテは 1 回の予約〜接客後の流れであり、いま動いているカルテが上にあるほうが書く人にも読む人にも役立つ |
| ホームの新着の並び順 | 最新の出来事の発生日の新しい順。同じ日はカルテを作った日時の新しい順 | ユーザーの判断。接客日の順に並べる |
| 旧カルテ 3 表の削除 | 第 4 段で行う | 第 2 段（参照を外す）と同じ deploy に入らないようにする（lambda README の 2 回デプロイの規則） |

### Constraints

- 第 1 段の constraint（作成ボタンの花形メニュー、FAB、ブレークポイントを変えない）を引き継ぐ
- シートは第 1 段の `SideSheet`（右からスライド、戻る操作で閉じる）を使う
- 第 2 段の業務ルール（星は完了するときに必須、補足必須の対応結果、出来事は 1 件以上、作成者だけが操作できる）は変えない
- 本段の migration はアプリの入れ替え前に流れる（`dystopia/lambda/README.md`）。そのため、第 2 段のアプリが新しい列を知らなくても動くように、列には既定値を持たせる

## Goals

- カルテのカード、詳細シート、作成・追記・編集のフォーム、ゲストのプロフィールの信頼性の見出し、自分のカルテの画面をモックの形にする
- 自分のカルテに、全体・記録中・完了の件数を出す
- 一覧の並び順を、自分のカルテとプロフィールは最後の動き、ホームは最新の出来事の発生日にする

## Non-goals

- カルテ以外の画面（第 4 段）
- 旧カルテ 3 表の削除（第 4 段）
- 一覧の絞り込み（#1519 では未決定）
- ゲスト本人へのカルテ表示（#1519 では未決定）
- 変更履歴、監査ログ（#1519 §9.2 の MVP 対象外）

## Screens

### Card (`KarteCard`)

ホームの新着、ゲストのプロフィール、自分のカルテで共通に使う。上から次を出す。

1. 小見出し「KARTE / キャストからゲストへ」
2. 記録者のアイコン・表示名と、最後の動きの相対時刻
3. 押せる枠（押すと詳細シートを開く）
   - ゲストの表示名と `@username`、右端に星（`★ 4.0` または「未評価」）
   - 最新の出来事を 1 行で「10/14 · 接客 · 途中終了 — 補足」（補足がなければ「 — 補足」を省く）
   - 状態の印（記録中は警告色、完了は緑）と、最新の出来事のタグを 2 つまで
4. 枠の外に「ゲストのプロフィールを見る →」

一覧ごとの違い:

| 一覧 | 違い |
|---|---|
| ゲストのプロフィール | 「ゲストのプロフィールを見る →」を出さない |
| 自分のカルテ | 今と違うプロフィールで書いたカルテに「@xxx として記録」（削除したプロフィールなら「削除したプロフィールで記録」）を出す |

カードの中には操作を置かない。

### Detail sheet (`KarteDetailSheet`)

見出しは「カルテの詳細」。上から次を出す。

1. 「KARTE / 記録中」または「KARTE / 完了」
2. ゲストのアイコン・表示名と「`@username` · 記録者 ○○」
3. 大きな星の数字（未評価なら「—」）と状態の印、その下に一言
   - 記録中: 「記録中のため平均評価には含まれません」
   - 完了: 「完了済みの評価は平均に反映されます」
4. 「予約から接客後までの記録」: 出来事を古い順（発生日、同じ日は作った順）に、段階 · 対応結果、タグ、補足、発生日

作成者には次を出す。

| 状態 | 操作 |
|---|---|
| 記録中 | 星のボタン（押すと保存。選んでいる星をもう一度押すと未評価に戻す）、各出来事の「編集」「削除」、「＋ 段階を追記する」、下部に「完了する」 |
| 完了 | 下部に「再オープン」 |
| どちらも | 「このカルテを削除」（確認のダイアログを出す） |

- 出来事が 1 件のときは「削除」を押せなくし、「出来事は 1 件以上必要です」と添える
- 星がないときは「完了する」を押せなくし、「完了するには星を選んでください」と添える
- 「＋ 段階を追記する」と「編集」は、シートの中でフォームの画面に進む（見出しの戻るボタンで詳細に戻る）。保存したら詳細に戻る
- 完了・再オープンは、シートを開いたまま状態の印と一言を切り替える（#1519 §8.6）
- 削除したらシートを閉じる

トースト:

| 操作 | 文言 |
|---|---|
| 追記 | カルテに追記しました |
| 出来事の編集 | 出来事を更新しました |
| 出来事の削除 | 出来事を削除しました |
| 完了 | カルテを完了しました。平均評価へ反映します |
| 再オープン | カルテを再オープンしました。集計から一時除外します |
| カルテの削除 | カルテを削除しました |

シートは開いたカルテの id を持ち、1 件取得の hook（`useKarte`）で中身を読む。一覧が持っているカルテを初期値に渡し、開いた瞬間に中身を出す。操作が成功しても失敗しても、表示中のカルテの一覧と詳細をすべて取り直す（`revalidateKarte()`）。失敗したときは、サーバーのメッセージをシートの上部に出す。

開いたカルテが見つからなくなった（他のタブで削除された）ときは、シートを閉じる。

### Event form (`KarteEventForm`)

作成・追記・編集で共通に使う。上から次を出す。

1. ゲストの小さなカード: アイコン・表示名と「`@username` · すべてのキャストに共有」
2. 記録する段階: 「予約・問い合わせ」「接客」「接客後」の 3 つのボタン。段階を変えたら、対応結果をその段階の最初の候補に戻し、タグを外す
3. 対応結果: 選択欄（候補は第 2 段の `lib/catalog.ts`）
4. 詳細タグ（任意）: 押すたびに選ぶ・外すが切り替わるボタン（`aria-pressed`）
5. 補足: 普段は「補足（任意）」、補足必須の対応結果では「補足（必須）」。必須で空なら保存ボタンを押せない
6. 発生日: 日付。既定は今日（日本時間）
7. 予約・接客の信頼性: 作成のときだけ出す。星のボタン、初期値なし。添える一言は「3.0 が標準。評価はカルテ全体につき 1 つです。星は完了するときに必要です」

保存ボタンとトースト:

| 用途 | ボタン | トースト |
|---|---|---|
| 作成 | 記録中のカルテを作成 | 記録中のカルテを作成しました |
| 追記 | この段階を追記 | カルテに追記しました |
| 編集 | 出来事を更新 | 出来事を更新しました |

入力中の内容は、シートを閉じるまで残す。保存に失敗しても消さない。編集のときは、その出来事の値を初期値にする。

### Rating input (`KarteRatingInput`)

★ のボタンを 5 つ並べる。各ボタンの読み上げ名は「N つ星」、選んでいる星までを塗る。選んでいる星をもう一度押すと未評価（`null`）に戻す。作成フォームと詳細シートで使う。

### Guest profile karte tab (`GuestKarteTab`)

1. 信頼性の見出し（`KarteReliabilityHeader`）
   - 左: 平均の大きな数字（小数 1 桁、なければ「—」）と、四捨五入した数の ★（なければ「未評価」）
   - 右: 「予約・接客の信頼性（参考評価）」と「N人が評価 · M件の完了済みカルテ」
2. カードを最後の動きの新しい順に並べる。カルテがなければ「カルテはまだありません」
3. 一番下に「このゲストのカルテを書く」。ゲストを選び済みの作成シートを開く

### My karte (`/karte/my`)

1. 見出し「自分のカルテ」と「自分が作成したカルテの一覧。ホームの「カルテ」は全キャストの新着です。」
2. 「＋ カルテを作成」: 作成メニューと同じく、ゲストを選ぶところから作成シートを開く
3. 件数の欄: 自分のカルテ・記録中・完了。同じアカウントのすべてのプロフィールで書いたカルテを数える
4. カードを最後の動きの新しい順に並べる。なければ「自分のカルテはまだありません」

キャストでない閲覧者への表示と、ログイン状態の読み込み中の表示は第 2 段のまま。

### Home karte tab

カードを新しいものに替え、最新の出来事の発生日の新しい順に並べる。記録中のカルテも載せることは第 2 段のまま。

### Compose

作成メニューの「カルテ」は、今の `ComposeToSheet` のまま（ゲストを選ぶ → 作成フォーム）。作成フォームを `KarteEventForm` に替える。プロフィールの「このゲストのカルテを書く」からは、ゲストを選び済みの状態で同じシートを開く（`ComposeToSheet` に初期のゲストを渡す）。保存したらトーストを出し、`revalidateKarte()` で表示中のカルテの一覧と詳細を取り直す。

### Removed

`KarteEntryCard`、`KarteComposer`、`KarteEventFields`、`KarteRatingSelect`、`KarteAggregateHeader` と、それぞれのテストを削除する。開発用のカタログ（`/dev/ui/karte`）は新しい部品に替える。

## Backend

### Ordering columns

`karte.kartes` に 2 列を足す。

| 列 | 型 | 制約 | 意味 |
|---|---|---|---|
| `last_activity_at` | timestamptz | not null、既定値 `now()` | 最後の動きの日時 |
| `last_occurred_on` | date | not null、既定値 `CURRENT_DATE` | 出来事の発生日の最大値 |

migration で、既存の行の `last_activity_at` に `updated_at` を、`last_occurred_on` に出来事の発生日の最大値を入れる。既定値は、migration の後でアプリが入れ替わるまでの間に第 2 段のアプリが作る行のためにある。この間に作られた行の `last_occurred_on` は出来事の発生日とずれうるが、次に出来事を変えたときに直る。

列を更新する操作:

| 操作 | `last_activity_at` | `last_occurred_on` |
|---|---|---|
| 作成 | 作った日時 | 最初の出来事の発生日 |
| 出来事の追加 | 更新する | 出来事の発生日の最大値に更新する |
| 出来事の編集・削除 | 更新しない | 出来事の発生日の最大値に更新する |
| 星の変更 | 更新しない | 更新しない |
| 完了・再オープン | 更新する | 更新しない |

出来事の編集と星の変更で `last_activity_at` を更新しないのは、誤字を直しただけで先頭に上がらないようにするため。更新は第 2 段の行ロックを取った transaction の中で行う。

索引は、作った日時の一覧用 3 つを次に替える。

- `(target_profile_id, last_activity_at DESC, id DESC)`: ゲスト別の一覧
- `(author_account_id, last_activity_at DESC, id DESC)`: 自分の一覧
- `(last_occurred_on DESC, created_at DESC, id DESC)`: 新着

cursor は並び順の列をそのまま持つ（ゲスト別と自分の一覧は `last_activity_at` と `id`、新着は `last_occurred_on`・`created_at`・`id`）。読んでいる間に動いたカルテは、続きのページで重複したり抜けたりしうる。frontend は id で重複を除く。

### RPC changes

- `Karte` に `last_activity_at`（Timestamp）、`author_display_name`、`target_display_name` を足す。表示名は presenter が既に読んでいるプロフィールから取る。プロフィールがなければ空文字
- `ListMyKartesResponse` に `KarteCounts counts`（`total_count`・`open_count`・`closed_count`）を足す。`open` という項目名は Ruby の protobuf で `Kernel#open` と衝突しうるため避ける。cursor のない最初のページでだけ数え、続きのページでは 0 を返す。作成者のアカウントで絞り、状態ごとに数える 1 回の問い合わせで求める

proto のスタブは `bin/codegen`（monolith）と `pnpm proto:gen`（frontend）で再生成し、`karte` package の差分だけを commit する。

### Frontend data

- 型: `Karte` に `lastActivityAt`・`authorDisplayName`・`targetDisplayName`、`MyKartePage` に `counts` を足す
- BFF: `/api/karte/my` の応答に件数を通す
- hook:
  - `useKarte(id, initial)`: 1 件取得。第 2 段から持ち越した
  - `useMyKarte`: 最初のページの件数を返す
  - 一覧の hook は id で重複を除く
  - `revalidateKarte()`: カルテの一覧と詳細の hook が登録した取り直し関数をすべて呼ぶ。操作の hook は成功・失敗のどちらでも呼ぶ。SWR の全体 `mutate` に関数でキーを渡す方法は、useSWRInfinite のキー（`$inf$` で始まる）を対象から外すため、一覧を取り直せない（swr 2.5.1）

## Testing

monolith（rspec）:

- 並び順: ゲスト別と自分の一覧は最後の動きの順、新着は最新の出来事の発生日の順（同じ日は作った順）。cursor で続きが取れる
- 列の更新: 出来事の追加・完了・再オープンは `last_activity_at` を進め、出来事の編集・星の変更は進めない。出来事の追加・編集・削除で `last_occurred_on` が最大値になる（さかのぼった日付を足しても下がらない、最大の出来事を消すと下がる）
- 件数: 状態ごとに数える、同じアカウントの別プロフィールの分を含める、別アカウントの分を含めない、続きのページでは 0
- migration: 既存の行に値が入る
- presenter: 表示名と `last_activity_at` を返す

frontend（vitest）:

- `KarteCard`: 一覧ごとの違い、最新の出来事の 1 行、タグ 2 つまで、未評価の表示、枠を押すと開く
- `KarteDetailSheet`: 作成者にだけ操作が出る、状態ごとの操作、出来事 1 件では削除を押せない、星がないと完了を押せない、追記・編集でフォームに進んで戻る、失敗してもキャッシュを取り直す
- `KarteEventForm`: 段階を変えると対応結果とタグが戻る、補足必須で空なら保存できない、編集では出来事の値が入っている、作成のときだけ星が出る
- `KarteRatingInput`: 押すと値が変わる、同じ星をもう一度押すと `null`
- `KarteReliabilityHeader`: 数字・星・人数・件数、未評価
- 自分のカルテ: 件数の欄
- `revalidateKarte`: 登録した関数をすべて呼び、登録を外した関数は呼ばない

実機（使い捨て DB、puppeteer）: 作成 → 追記 → 出来事の編集 → 星 → 完了 → 平均 → 再オープン → 件数 → 並び順（自分のカルテで、追記したカルテが先頭に上がる）を確かめる。
