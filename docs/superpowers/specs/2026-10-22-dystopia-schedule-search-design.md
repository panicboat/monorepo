# Dystopia schedule search design

## Context

#1549 は、出勤の予定からキャストを探せる画面を求めている（issue 添付のプロトタイプ `dystopia_shift_discovery_prototype.html`）。プロトタイプは、出勤日（直近 14 日）・エリア・勤務時間帯・「フォロー中だけを見る」で絞り、キャストごとのカード（名前・エリア・出勤時間・ひとこと・フォロー・プロフィール）を並べる。

今は、予定はキャストのプロフィール（予定タブと今週の予定）でしか見られない。予定は鍵の有無にかかわらず誰でも見られる（鍵が制限するのは投稿だけ）。

### Decisions taken before this spec

| 論点 | 決定 | 理由 |
|---|---|---|
| 置き場所 | 既存の検索画面に「出勤」タブを足す（新しいナビ項目は作らない） | ユーザーの判断。人を見つける場所を 1 つにまとめる |
| 検索ボックス | 出勤タブでは名前・@username の絞り込みに使う。空なら全員 | 既存の検索ボックスをそのまま活かす |
| エリア | プロフィールの都道府県で絞る。出勤ごとの地域（新宿・池袋など）は別 issue | ユーザーの判断。ホームのエリアタブと同じ単位 |
| 出す相手 | キャストだけ。鍵付きも含める。ブロック（両方向）・停止中・無効化は除く | 予定はもともと誰でも見られる。ブロックと停止は既存の検索と同じ扱い |
| ひとこと | #1511 のお知らせ投稿があり、見る人がその投稿を見られるときだけ本文を出す | 予約中・表示終了・フォロワーのみの投稿の本文を漏らさない |
| 「最近の投稿を見る」 | 置かない | プロフィールの初期タブが投稿なので「プロフィール」と行き先が同じ |
| 名前 | 識別子・URL・RPC は schedule（`schedules`）。shift は使わない | ユーザーの判断。以前に shift から schedule へ改名済み |

## Goals

- 検索画面の「出勤」タブで、出勤日・都道府県・勤務時間帯・フォロー中だけ・名前で、その日に出勤するキャストを探せる
- 結果のカードからフォローとプロフィールに進める

## Non-goals

- 出勤ごとの地域（別 issue）
- 予約の空き・受付可否
- ホームの帯・右サイドのカードなど、検索以外の入口
- 並びの変更（開始時刻順のみ）

## Rules

### Filters

| 絞り込み | 選択肢 | 初期値 |
|---|---|---|
| 出勤日 | 今日から 14 日分（日本時間） | 今日 |
| エリア | 全国、47 都道府県（`PREFECTURES`） | 全国 |
| 勤務時間帯 | すべて／昼（5〜18時）／夜（18〜21時）／深夜（21時〜翌5時） | すべて |
| フォロー中だけを見る | オン／オフ（オンなら承認済みでフォローしている相手だけ） | オフ |
| 名前 | 検索ボックスの文字（display_name・username の部分一致、大文字小文字を区別しない） | 空（全員） |

名前の先頭の `@`（全角の `＠` も）は無視する。カードは `@suzu_21` と表示するので、`@suzu` で `suzu` を探せる。monolith の `Discovery::UseCases::SearchSchedules` が、前後の空白を除いた名前から先頭の `@`・`＠` を外してから渡す（`@` だけなら名前なしと同じ）。

検索ボックスの placeholder は、出勤タブでは「名前で絞り込む」にする。ユーザー・投稿タブは「ユーザーや投稿を検索」のまま。

勤務時間帯は、勤務時間がその時間帯と少しでも重なるかで決める（ユーザーの判断。開始時刻だけで決めると、16:00〜22:00 の人が「夜」に出ないため）:

- 昼: 05:00〜18:00、夜: 18:00〜21:00、深夜: 21:00〜翌 05:00（どれも終わりの時刻は含まない）
- 勤務時間は営業日で数える。開始が 05:00 より前なら翌日の時刻、終了が開始以下なら終了は翌日
- 例: 16:00〜22:00 は昼・夜・深夜、20:00〜02:00 は夜・深夜、12:00〜18:00 は昼だけ、01:00〜05:00 と 04:00〜06:00 は深夜だけ

### Order and paging

- 開始時刻の早い順。ただし 00:00〜04:59 の開始は 23:59 の後ろに並べる（夜の出勤の続きとして）
- 同じ開始時刻はプロフィール ID 順
- 20 件ずつ、カーソルで続きを読む

### Card

```
┌──────────────────────────────────────────┐
│ す  すず @suzu_21                 東京都 │
│ 久しぶりの出勤。よろしくお願いします。    │  ← ひとこと（あるときだけ。投稿の本文と同じく枠の上）
│ ┌──────────────────────────────────────┐ │
│ │ 出勤                                  │ │
│ │ 16:00〜22:00                          │ │  ← 時間を太字・大きめ
│ │ 📦 10/22（木）                        │ │
│ └──────────────────────────────────────┘ │
│                 [＋フォロー] [プロフィール →] │
└──────────────────────────────────────────┘
```

- 出勤時間は「開始〜終了」。終了が開始以下、または開始が 05:00 より前なら終了の後ろに「翌日」（05:00 より前の開始は出勤日の夜の続き。`crossesMidnight`）
- 出勤の枠は投稿の出勤カードと同じ部品（`ScheduleSummary`）で描く。業種アイコンは枠の中の日付の前（`industryIcon`、読み上げ名は業種名、未設定・一覧にないときは出さない）。名前の行の右は都道府県だけ
- フォローは既存の `FollowButton`。自分のプロフィールには出さない
- アバター・名前・出勤の枠・「プロフィール →」は、プロフィールの予定タブ（`/u/<username>?tab=schedule`）を開く
- 結果の上に見出し「10/22（木）の出勤予定」を出す。件数は出さない（ページ送りなので総数が分からない）
- 結果の下の注記: 「キャストが公開した出勤予定です。予約の空きや受付可否を保証するものではありません。」
- 結果がないとき:
  - エリアが全国でない、勤務時間帯がすべてでない、「フォロー中だけを見る」がオン、名前（前後の空白を除いて）が空でない、のどれかが入っているとき: 「条件に合う出勤予定はありません」
  - どれも入っていないとき（出勤日だけを変えた場合を含む）: 「この日の出勤予定はまだありません」
  - 検索中・読み込みの失敗の文言はこれまでどおり

### URL

検索画面は、タブと出勤タブの絞り込みを URL に書き（`router.replace`。履歴を増やさず、スクロール位置も動かさない）、読み込み時に読み戻す。カードからプロフィールへ進んで戻っても、タブと絞り込みが残る。

| パラメータ | 値 | 書くとき | 読めない値のとき |
|---|---|---|---|
| `q` | #タグなど、開いたときの検索文字 | 既存の挙動のまま。画面は書き換えず、`q` があれば残す | — |
| `tab` | `users`／`posts`／`schedules` | タブを切り替えるたび | 既存どおり（`#` で始まる `q` なら投稿、それ以外はユーザー） |
| `date` | `YYYY-MM-DD` | 出勤タブで、今日以外を選んでいるとき | 今日（14 日の範囲外・日付でない値） |
| `prefecture` | 都道府県名 | 出勤タブで、全国以外を選んでいるとき | 全国（47 都道府県にない値） |
| `timeBand` | `day`／`evening`／`night` | 出勤タブで、すべて以外を選んでいるとき | すべて（この 3 つにない値） |
| `following` | `1` | 出勤タブで、オンのとき | オフ（`1` 以外） |

- 初期値のままの絞り込みは書かない。出勤タブ以外では `date`・`prefecture`・`timeBand`・`following` を URL から外す
- タブを切り替えて出勤タブへ戻したときは、選んでいた絞り込みを画面が覚えていて、URL にも書き直す
- 検索ボックスに打った文字は URL に書かない（既存の挙動）。画面を作り直すのは `q` が変わるとき（#タグのリンクを開いたとき）だけで、`tab` と絞り込みの書き込みでは作り直さない

## Architecture

### Proto (`discovery.v1`)

```proto
rpc SearchSchedules(SearchSchedulesRequest) returns (SearchSchedulesResponse);

message SearchSchedulesRequest {
  string work_date = 1;      // YYYY-MM-DD
  string prefecture = 2;     // 空は全国
  string time_band = 3;      // "" | "day" | "evening" | "night"
  bool following_only = 4;
  string query = 5;
  int32 limit = 6;
  string cursor = 7;
}

message ScheduleSearchResult {
  schedule.v1.Schedule schedule = 1;
  profile.v1.ProfileSummary profile = 2;
  string prefecture = 3;
  string note = 4;           // 見る人に見えるお知らせ投稿の本文。なければ空
}

message SearchSchedulesResponse {
  repeated ScheduleSearchResult results = 1;
  string next_cursor = 2;
  bool has_more = 3;
}
```

不正な `work_date`・`time_band` は INVALID_ARGUMENT。

### Monolith

- `Discovery::UseCases::SearchSchedules`（既存の `SearchPosts`・`SuggestUsers` と同じく、他の slice の repository / use case を組み合わせる）:
  1. 対象のプロフィール ID: profile の repository に、表示可能なキャストを都道府県・名前で絞って ID を返すメソッドを足す（`identity.accounts.role` は既存の `filter_by_role` と同じ副問い合わせ）。フォロー中だけなら social のフォロー中 ID と交わす。両方向のブロック ID を除く
  2. 予定: schedule の repository に、出勤日・勤務時間帯・プロフィール ID で絞り、上の並びとカーソルで引くメソッドを足す。出勤日で引けるように `schedule.schedules` に `(work_date, start_time)` の index（`idx_schedule_schedules_work_date_start_time`）を張る
  3. 作者: `SummarizeProfiles`（業種を含む）。都道府県は同じ問い合わせか、ID でまとめて引く
  4. ひとこと: そのページの `post_id` をまとめて、見る人に見える投稿だけに絞って本文を引く（`ListReadablePostIds` か `FilterVisiblePosts` を通す。1 回の問い合わせ）
- discovery handler に `search_schedules`。認証は既存の検索と同じ

### Frontend

- 検索画面（`src/app/search/page.tsx`）に「出勤」タブ（id `schedules`）。URL の `?tab=schedules` で開ける。タブと絞り込みの URL への書き込みと読み戻しは上の URL の節のとおりで、検索画面が持つ
- 出勤タブの中身は `src/modules/schedule/` に部品として置く（絞り込みとカードの一覧）。検索ボックスの文字を名前の絞り込みに渡す。絞り込み（出勤日・エリア・勤務時間帯・フォロー中だけ）は検索画面が持ち、部品には値と変更の通知を渡す
- 絞り込みの初期値・URL の読み書き・不正な値の戻し先は `src/modules/schedule/lib/searchChoices.ts` にまとめる
- BFF `GET /api/discovery/schedules`（既存の discovery の BFF route に合わせる）
- 日付チップの表示は既存の `formatDayLabel` などを使う

## Testing

monolith（rspec）:

- 出勤日・都道府県・勤務時間帯（勤務時間の重なり。区切りちょうどで終わる勤務は次の時間帯に入らない、日をまたぐ勤務・05:00 前の開始）・フォロー中だけ・名前で絞れる
- キャストだけ。鍵付きは出る。ブロック（両方向）・停止中・無効化は出ない
- 並び: 21:00 → 23:00 → 00:30 → 04:00 の順。カーソルで重複・抜けなく送れる
- ひとこと: 見える表示中のお知らせは本文が入る。予約中・表示終了・フォロワーのみ（見る人が承認済みフォロワーでない）のお知らせは空
- 不正な `work_date`・`time_band` は INVALID_ARGUMENT
- 名前の先頭の `@`・`＠` は無視する（`@suzu` で `suzu`）
- マイグレーション: `schedule.schedules` に `(work_date, start_time)` の index ができ、down で消える

frontend（vitest、`tsc --noEmit --incremental false`）:

- 出勤タブの初期値（今日・全国・すべて・オフ）と、絞り込みを変えたときの BFF への問い合わせ
- 検索ボックスの文字が名前の絞り込みに入る。`?tab=schedules` で出勤タブが開く。placeholder は出勤タブだけ「名前で絞り込む」
- URL: タブを切り替えると `tab` が、出勤タブで絞り込みを変えると `date`・`prefecture`・`timeBand`・`following` が `router.replace` で書かれる。`tab=schedules&date=<明日>&prefecture=東京都&timeBand=night&following=1` で開くと絞り込みが戻り、範囲外の日付・不明な都道府県・不明な時間帯は既定値に戻る。`q` が変わると画面を作り直し、`tab` が変わるだけでは作り直さない
- カード: 「翌日」（終了が開始以下／開始が 05:00 より前）、業種アイコン、ひとこと（あるときだけ）、自分にはフォローボタンを出さない、注記
- 空の表示: 絞り込みが入っているときは「条件に合う出勤予定はありません」、入っていないときは「この日の出勤予定はまだありません」

ローカルの実機:

- 今日の予定を入れたキャストが出勤タブに出て、時間帯・都道府県・フォロー中だけで出たり消えたりする
- お知らせ投稿のひとことがカードに出る
