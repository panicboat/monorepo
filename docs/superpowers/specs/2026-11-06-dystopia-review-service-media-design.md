# Review Service Media Design

Issue: #1949

## Intent

クチコミの「利用」の出来事に、画像と動画を添付できるようにする。
ゲストのレポには、終わった後のキャストを撮った写真を載せる文化がある。
加工の少ない写真で、雰囲気や体型を共有する目的もある。
活発なゲストがレポを書きやすい土壌を作ることが狙い。

## Goals

- ゲストが、クチコミの「利用」の出来事に画像と動画を添付できる。
- クチコミを見られる人が、添付された画像と動画を見られる。

## Non-goals

- カルテへの添付は作らない。
  - 使われる見込みが小さいため。
  - Issue にも切り出さない。
- 「予約・問い合わせ」「利用後」の出来事への添付は作らない。
  - 「利用後」は会った後の連絡やトラブルを記録する段階で、写真の目的に合わないため。
- 動画のサムネイルは作らない。
  - #1951 で扱う。
- 通報の理由に「無断撮影」などの選択肢は足さない。
  - 前提を外れた写真は、既存のクチコミの通報で「その他」を選んで知らせる。

## Anti-goals

- 写真付きクチコミが、キャストを晒す道具になること。
  - 写真は、キャスト本人の同意を得て撮った、服を着た状態のものが前提。
  - 前提を外れた写真は、通報を受けて運営者が規約の「違反への措置」で対応する。
- クチコミ本文を見られない人に、写真の配信 URL が渡ること。

## Current State

- クチコミは、出来事（`reservation` / `service` / `aftercare`）を積み上げる作り（`dystopia/docs/features/reviews.md`）。
  - 画面の段階名は「予約・問い合わせ」「利用」「利用後」。
  - 出来事は段階・対応結果・タグ・補足・発生日を持つ。
- 投稿とコメントには添付があり、これを手本にする。
  - 添付の行: `post.post_media`・`post.comment_media`（`media_id` は FK なしの参照、`media_type`、`position`）。
  - 所有の検査: `Post::Adapters::MediaAdapter#owned_all?` が `Media::Slice["use_cases.select_owned_media_ids"]` を呼ぶ。
  - 配信 URL: `Media::Slice["use_cases.get_media_batch"]` で取得のたびに署名する（`dystopia/docs/features/media.md`）。
  - 削除時の片付け: `Post::UseCases::DiscardDetachedMedia` が、投稿・コメント・アバター/カバーのどれにも使われていないメディアだけを `discard_media` に渡す。
  - 画面: 添付の選択とアップロードは `modules/media/hooks/useMediaUpload.ts`、添付一覧は `modules/post/components/PostComposerAttachments.tsx`、表示は `components/ui/post-card.tsx`。

## Decisions

### 添付できる出来事

- 段階が `service`（利用）の出来事だけに添付できる。
- 1 つの出来事に、画像と動画を合わせて 4 件まで。
  - 投稿と同じ上限にした（私の判断）。
  - 画面とサーバーの両方が検査する。
- 添付できるのは、使っているプロフィールがアップロードしたメディアだけ。
  - 投稿・コメントと同じ規則。
- 添付は必須ではない。

### 付け外しの経路

- クチコミ作成時の最初の出来事、出来事の追加、出来事の編集の 3 つで添付を送れる。
- 出来事の編集は、添付の一覧を送られたもので置き換える。
  - 外された添付は、後述の片付けの対象になる。
- `service` 以外の段階で添付を送ったら拒否する（400）。
- `service` の出来事を別の段階に編集するときは、添付を空で送る必要がある。
  - 画面は、段階を `service` から切り替えたときに添付を外す（タグを外すのと同じ）。

### 閲覧

- 添付の配信 URL は、出来事を返すときに、そのクチコミの閲覧条件を通ったものにだけ付く。
  - 閲覧条件は `reviews.md` の既存の規則のまま。
- 鍵付きのゲストの名前を伏せる場合も、添付は本文と同じく返す。
- 対象キャストが有効でないときは、添付を作者アカウントにだけ返す。
  - 本文は名前を伏せて書き手の「書いたクチコミ」一覧と個別表示に残るが、写真では名前を伏せても本人と分かるため。
  - 作者アカウントには、自分で上げた写真を編集や削除のときに確かめられるよう返す。
    - 同じアカウントの別プロフィールを使っているときも同じ。
  - 対象キャストが有効に戻ると、元どおり見える。
- 添付先のメディアが消えている場合は、その添付を返さない。
  - 書き手のプロフィールの削除・purge でメディアは消えるが、クチコミの本文は残る。

### 通報と運営者の対応

- 通報の写しに添付は含めない。
  - `reports.md` の「画像と動画は写さない」に従う。
- 運営者が添付を 1 件だけ外す画面や API は作らない。
  - 通報は運営者が DB を見て対応する最小版のため、添付も DB の操作で外す。

### 画面

- クチコミの詳細では、出来事ごとに補足の下へ添付を並べる。
- 一覧のカードには、出来事の並びで最後にある添付付きの出来事の添付を、小さく並べる（私の判断）。
  - カードが出している最新の出来事が `aftercare` でも、写真がカードから消えないようにするため。
  - 添付を返さない閲覧者（上の「閲覧」）には、カードにも出さない。
- 出来事のフォームは、段階が「利用」のときだけ添付の欄を出す。
- 表示とアップロードは、投稿の部品を流用する。

### 削除時の片付け

- 出来事の削除、出来事の編集で外れた添付、クチコミの削除（最後の出来事の削除を含む）で、外れたメディアを片付ける。
- 片付けるのは、投稿・コメント・アバター/カバー・クチコミの添付のどれにも使われていないメディアだけ。
- 投稿・コメントの削除の片付けも、クチコミの添付に使われているメディアを残すようにする。
  - 今の `DiscardDetachedMedia` はクチコミの添付を知らないため、投稿と同じメディアを添付したクチコミから写真が消えてしまう。

### 仕様書

- 次の仕様書を、実装と同じ PR で更新する。
  - `dystopia/docs/features/reviews.md`: 添付の規則・閲覧・画面・Data。
  - `dystopia/docs/features/media.md`: 用途、添付の所有の規則、配信 URL の条件、削除時の片付けにクチコミを加える。
  - `dystopia/docs/data-model.md`: 添付の表。

## Left to the Builder

- 添付の表の名前と置き場所（`review` スキーマの出来事に付く表を想定）。
- proto の形（`ReviewEventInput` と `ReviewEvent` に添付を足す。投稿・コメントの `media_id` / `media_type` の形に合わせる）。
- 「どこにも使われていないか」の判定を、post と review のどちらの slice に置くか、または共通の場所に移すか。
  - slice 間の呼び出しは、既存の adapter の形に合わせる。
- 画面の部品を、post モジュールから共通の場所へ移すかどうか。
