# Video Thumbnail Design

Issue: #1951

## Intent

iPhone で動画付きの投稿を見ると、再生前の動画が黒い枠になり、どんな動画か分からない。
動画の一部分でも見えていれば、流し見しているときに中身の見当がつく。
動画から 1 コマを切り出してサムネイルにし、再生前の表紙として表示する。

## Goals

- アップロードした動画に、動画の中の 1 コマのサムネイルが付く。
- タイムライン・投稿の詳細・クチコミ・引用・投稿の作成中のプレビューで、再生前の動画がそのコマで表示される。
- サムネイルの無い動画も、iPhone で黒い枠にならない。

## Non-goals

- タイムラインでの自動再生と、gif や短い動画の生成は作らない。
  - 止まった 1 コマで足りるとユーザーが判断したため。
  - 自動再生は元の動画を丸ごと読み込み、短い動画の生成はサーバーでの変換の仕組みが要る。
- サーバーで動画を変換・圧縮する仕組みは作らない。
- 今ある動画にサムネイルを作り直す処理は作らない。
  - 表示側の代わりの描き方で黒い枠を避ける（後述）。
- メディアを CDN のキャッシュから配信する変更は入れない。
  - #1961 で扱う。
  - 今は S3 の署名付き URL で直接配信しており、この設計はその上で成り立つ。

## Anti-goals

- サムネイルを作れないことで、動画のアップロードが失敗すること。
- 表紙を出すために、タイムラインが元の動画を今より多く読み込むこと。

## Current State

- 画像は、画面で長辺 2048 px の本体と長辺 640 px のサムネイルの 2 つの JPEG に描き直して送る（`dystopia/docs/features/media.md`、`modules/media/lib/resize.ts`）。
  - サムネイルは、本体と同じ発行・PUT の経路で送り、登録で `thumbnailKey` として渡す（`modules/media/hooks/useMediaUpload.ts`）。
- 動画は、メタデータの入るボックスを書き換えた元のファイルだけを送り、サムネイルは作らない（`useMediaUpload.ts` の `prepareUpload`）。
- サーバーは種別に関係なくサムネイルのキーを受け取り、配信 URL を返し、削除で本体と一緒に消す。
  - 登録: `Media::UseCases::RegisterMedia` がサムネイルのキーの所有だけを確かめる。
  - 配信: 投稿・コメント・クチコミの出来事は `thumbnail_url` を返す。
- 動画の表示
  - タイムライン・投稿の詳細・クチコミ（`components/ui/media-gallery.tsx`）は、`<video controls playsInline preload="metadata">` で、表紙が無い。
    - iPhone の Safari は、表紙の無い動画を再生前に描かないため、黒い枠になる。
  - 投稿の作成中のプレビュー（`PostComposerAttachments.tsx`）とクチコミのフォーム（`ReviewEventAttachments.tsx`）は、`<video muted>` の小さな四角で、iPhone では黒い。
  - 引用の中（`QuoteFrame.tsx`）は、動画のサムネイルを画像として出し、無ければ「動画」という文字を出す。
- 動画の配信 URL は CloudFront を通らず、S3 から直接届く。

## Decisions

### サムネイルの作り方

- 動画を送るとき、画面で動画の 1 コマを切り出し、長辺 640 px の JPEG にしてサムネイルとして送る。
  - 大きさと画質は画像のサムネイルと同じ（`THUMBNAIL_MAX_EDGE`・`THUMBNAIL_QUALITY`）。
  - 送り方と登録は画像のサムネイルと同じ経路を使う。
  - サーバーは変えない。
- 切り出す位置は 1 秒。
  - 1 秒より短い動画は、長さの半分の位置にする。
  - Issue の「動画開始 1 秒とかのスクショ」に合わせた。
- メタデータを書き換える対象の形式（MP4・MOV・M4V・3GP）でも、それ以外の形式でも切り出す。
- 切り出せなかったときは、サムネイル無しで動画だけを送る。
  - 端末が動画を描けない（PC のブラウザで HEVC の MOV を選んだ等）、決めた時間内に描けない、などの場合。
  - 利用者にエラーは出さない。
- 切り出しには時間の上限を設け、超えたら切り出せなかったものとして扱う。
  - 上限の値は builder に任せる。
- サムネイルの発行または PUT が失敗したときも、サムネイル無しで動画を登録する（私の判断）。
  - Anti-goals の「サムネイルを作れないことでアップロードが失敗すること」を避けるため。
  - 本体を PUT した後にサムネイルだけ失敗して残ったオブジェクトは、登録しなかったオブジェクトと同じく、所有プロフィールの削除まで残る（`media.md` の Lifecycle）。
  - 画像のサムネイルの失敗は、今のままアップロード全体の失敗にする。
- 切り出しは、本体の PUT の前に行う（私の判断）。
  - 切り出しの失敗やタイムアウトで、アップロードは上限の時間だけ遅れる。
- 切り出しは、画面の中で一度に 1 本ずつ行う（私の判断）。
  - 投稿とクチコミのフォームは最大 4 本を並べて処理するため、同時に描くと iPhone のメモリが足りなくなる恐れがある。
  - 切り出し以外（本体とサムネイルの PUT）は今のまま並べて行う。

### 表示

- 再生前の動画は、サムネイルを表紙（`poster`）にして表示する。
  - タイムライン・投稿の詳細・クチコミの詳細とカード。
- 表紙のある動画は、再生を押すまで動画を読み込まない（`preload="none"`）。
- サムネイルの無い動画は、配信 URL の末尾に `#t=0.1` を付けて、iPhone にもそのコマを描かせる（私の判断）。
  - 今ある動画と、切り出せなかった動画が対象。
  - 読み込みは今と同じ `preload="metadata"`。
  - 再生は 0.1 秒の位置から始まる。
  - 黒い画面から始まる動画は黒いコマになる。
  - フラグメントはサーバーに送られないので、署名付き URL の署名は変わらない。
- 引用の中の動画は今のまま（サムネイルがあれば画像、無ければ「動画」の文字）。
  - サムネイルが付くので、新しい動画はコマが出るようになる。
- 投稿の作成中のプレビューとクチコミのフォームの四角は、切り出したサムネイルを画像として出す。
  - サムネイルが無いときは、`#t=0.1` を付けた動画にする。
  - 編集で送り直す既存の添付は、配信されたサムネイル URL を使う。

### 検証

- iPhone での切り出しと `#t=0.1` の表示は、デプロイ後に本番の iPhone で確かめる（ユーザーの決定）。
  - 自動テストの jsdom では動画を描けないため。
  - 計画に実機での試作は置かない。
  - 切り出せなくても動画は今どおり送れるので、通らなかったら直すか戻す。
- 自動テストでは、切り出す位置の計算、切り出しの失敗・タイムアウト・サムネイルの PUT の失敗でも動画が登録されること、表紙の有無による `poster`・`preload`・URL の切り替えを確かめる。

### 仕様書

- `dystopia/docs/features/media.md` の Rules に、動画のサムネイルの作り方と、切り出せないときの扱いを加える。
  - 実装と同じ PR で更新する。

## Left to the Builder

- 切り出しの時間の上限の値。
- 切り出しの処理を置く場所（`modules/media/lib/` に `resize.ts` と並べることを想定）。
- 作成中のプレビューで使う、サムネイルのローカル URL の持たせ方（`UploadedMedia` に足すなど）。
- 表紙の有無で `preload` と URL を切り替える処理を、どの部品に置くか。
