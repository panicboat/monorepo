# Dystopia schedule announcement design

## Context

出勤の予定は、プロフィールを開かないと見えない。#1511 は、キャストが予定を登録する → フォロワーが気づく → プロフィールを見る → 予約を相談する、という流れを求めている。issue の提案は「予定を登録するときに、投稿も作るかを選べる」こと。

予定は「予定をまとめて編集」のシート（`ScheduleBulkSheet`）で、最大 14 日分を選んで同じ時間帯を一括で入れる。1 日ごとに `SaveSchedule` を呼ぶ。#1585 で、投稿に表示開始・表示終了を指定できるようになった。

### Decisions taken before this spec

| 論点 | 決定 | 理由 |
|---|---|---|
| 投稿の出し方 | 予定を入れた日ごとに 1 件ずつ、その日のお知らせ時刻から出勤の終了まで表示する予約投稿を作る | ユーザーの判断。当日にフォロワーのタイムラインで新着として出る |
| 予定を変えたとき | 投稿も追従させる（時間を変えたら書き換え、予定を消したら投稿も消す） | ユーザーの判断。古い時間のお知らせを残さない |
| お知らせの時刻 | キャストがシートで選ぶ。初期値は 09:00 | ユーザーの判断 |
| 見せ方 | 投稿の本文はひとこと（任意）だけ。出勤日と時間は、カルテ・クチコミと同じ枠のカードで本文の下に出す | ユーザーの判断 |
| 出勤時間の持ち方 | 投稿には写さず、表示のたびに予定の行から引き、`schedule.v1.Schedule` として投稿に添える（作者の `profile.v1.ProfileSummary` と同じ形） | 予定を変えるとカードが自動で最新になり、同じ情報を 2 か所に持たない。タイムライン 1 ページあたり索引付きの問い合わせが 1 本増えるだけ（ユーザー了承） |
| 切り替えの初期値 | オン | ユーザーの判断。フォロワーに届くのがこの機能の目的 |
| 予定と投稿のつながり | 予定の行に `post_id` を持つ | ユーザーの判断。お知らせに限らない名前にしておく |
| 業種アイコン | カードの日付の前に、作者の業種のアイコン（プロフィール画面と同じ `industryIcon`）を出す。業種が未設定・一覧にないときはアイコンなし | ユーザーの判断 |
| 作る場所 | サーバー側（`SaveSchedule`・`DeleteSchedule`） | 画面側で作ると、予定の変更・削除への追従と途中失敗の扱いを画面が抱える |

## Goals

- 予定を入れるときに「投稿でお知らせする」を選べ、選ぶと日ごとにお知らせ投稿が予約される
- お知らせ投稿は、ひとことの下に出勤日と時間のカードを出す
- 予定の時間を変える・お知らせを外す・予定を消すと、お知らせ投稿もそれに合わせて変わる・消える
- キャストはお知らせの時刻とひとことを選べる

## Non-goals

- ひとことの #タグ・@メンションの解析（ただの文字として出す）
- 日ごとに違うひとこと（一括で入れた日は同じひとこと）
- お知らせ投稿の公開範囲の選択（「全員」で固定）
- 予定を入れたときの通知（フォロワーへのアプリ内通知や Web Push）

## Rules

### Terms

- **お知らせ時刻**: 出勤日のこの時刻（日本時間）から投稿を表示する
- **出勤の終了**: 出勤日は営業日で、終了は開始の日の終了時刻（日本時間）。終了時刻が開始時刻以下なら翌日のその時刻
- **出勤の開始**: 開始時刻が 05:00 より前の予定は、その出勤日の夜のもので、翌日のその時刻に始まる。お知らせ時刻は開始時刻にかかわらず出勤日のまま
  - 例（出勤日 10/24）: 20:00〜02:00 は 10/24 20:00 から 10/25 02:00、01:00〜05:00 は 10/25 01:00 から 10/25 05:00、23:30〜04:00 は 10/24 23:30 から 10/25 04:00
- **つながった投稿**: 予定の `post_id` が指す投稿。本人が投稿を消していれば、つながった投稿はないものとして扱う

### Saving a schedule

| お知らせ | つながった投稿 | 動き |
|---|---|---|
| オン | ない | 投稿を作り、`post_id` に入れる |
| オン | ある | 本文（ひとこと）と表示終了を書き換える。表示開始は、投稿がまだ予約中のときだけ書き換える |
| オフ | ある | 投稿を消し、`post_id` を空にする |
| オフ | ない | 何もしない |

- 作る・書き換える投稿:
  - 本文: ひとこと（空でもよい）
  - 表示開始: お知らせ時刻。すでに過ぎていれば今
  - 表示終了: 出勤の終了
  - 公開範囲: 全員
- 出勤の終了がもう過ぎている日には、オンでも投稿を作らない（つながった投稿があれば今のルールどおり書き換える）
- お知らせ時刻が出勤の終了以降なら INVALID_ARGUMENT「お知らせの時刻は出勤の終了より前にしてください」
- ひとことは 200 文字まで。超えたら INVALID_ARGUMENT「ひとことは200文字以内で入力してください」

### Deleting a schedule

つながった投稿があれば消す。

### Display

```
り  りん @rin · 3h
    お待ちしてます！            ← ひとこと（空なら出さない）
    ┌──────────────────────────┐
    │ 出勤                      │
    │ 20:00〜02:00 翌日         │  ← 時間を太字・大きめ
    │ 🚗 10/24（金）            │  ← 先頭は作者の業種アイコン
    └──────────────────────────┘  ← 押すとキャストのプロフィールの予定タブへ
```

- 出勤の枠は出勤検索のカードと同じ部品（`ScheduleSummary`）で描く

- 業種アイコンは読み上げ名に業種名を持つ（プロフィール画面と同じ）。業種が未設定・一覧にないときはアイコンを出さない
- カードの時間は、その時点の予定の時間（予定を変えればカードも変わる）
- 開始が 05:00 より前、または終了が開始以下の予定は、時間の後ろに小さく「翌日」を添える
- 返信の上に出る親投稿のプレビューは、本文が空なら「出勤 10/24（金）20:00〜02:00 翌日」の 1 行を出す

## Architecture

### Database

`schedule.schedules` に `post_id uuid NULL` と、`post_id IS NOT NULL` の部分索引（投稿から予定を引くため）。他の slice の表への FK は張らない（今のプロフィール ID と同じ扱い）。

### Proto

`post.v1`:

- `Post` に `schedule.v1.Schedule schedule = 15;`（つながった予定がなければ未設定）。`author` が `profile.v1.ProfileSummary` を参照するのと同じく、予定の型は schedule の定義をそのまま参照し、post.v1 に予定の概念を定義しない

`profile.v1.ProfileSummary` に `string industry = 7;`（作者の業種。カードのアイコンに使う。作者をまとめて引く既存の問い合わせで一緒に読むので、問い合わせは増えない）

`schedule.v1` の `SaveScheduleRequest` に足す:

- `bool announce = 4;`
- `string announce_time = 5;`（`HH:mm`。`announce` がオフなら無視）
- `string announce_note = 6;`

### Monolith

- schedule repository: `upsert` が `post_id` を返し、`post_id` を書き換える処理を足す
- `SaveSchedule`: 予定を保存したあと、上の表で投稿を作る・書き換える・消す。投稿は post slice の `PostRepository`（`create_post`・`update_post`・`delete_post`・`find_by_id`）で扱う
- `DeleteSchedule`: 予定を消す前に、つながった投稿を消す
- 時刻の計算（お知らせ時刻・出勤の終了）は 1 か所（schedule slice の小さな部品）にまとめる
- post の一覧・詳細の presenter（`ListPostsByIds` と post handler の presenter）は、投稿 ID の一覧で予定をまとめて引き（1 回の問い合わせ）、`Post.schedule` に入れる。予定は post の adapter（`Post::Adapters::ScheduleAdapter`、読み取りだけ）から schedule slice の repository に足す `find_by_post_ids(post_ids:)` で引く

### Frontend

- `ScheduleBulkSheet` の「予定を入れる」に:
  - 「投稿でお知らせする」の切り替え（初期値オン）
  - 「お知らせする時刻」（`TimeSelect`、初期値 09:00）
  - 「ひとこと」の入力（任意、200 文字まで）
- 「予定を消す」には「お知らせの投稿も消えます」と添える
- `PostView.schedule`（`{ workDate, startTime, endTime } | null`）。投稿カード（`PostCardBinding`）と詳細で、本文の下に出勤のカード（クチコミのカードと同じ枠、小見出し「出勤」）を出し、押すと `/u/<username>?tab=schedule`（プロフィールの予定タブ）へ
- 返信の親投稿のプレビューは、本文が空なら出勤の 1 行を出す
- `useSaveSchedule` と BFF の保存 route が `announce`・`announceTime`・`announceNote` を送る

## Testing

monolith（rspec）:

- お知らせオンで投稿ができ、表示開始・表示終了・本文・公開範囲が正しい
- 終了が日をまたぐ予定の表示終了が翌日になる。開始が 05:00 より前の予定は出勤日の翌日 05:00 などで終わり、出勤日の夜のあいだは終了していない
- お知らせ時刻を過ぎていれば表示開始が今になる。出勤の終了を過ぎた日には作らない
- 時間を変えると表示終了が変わり、投稿の `schedule` が新しい時間になる。表示中の投稿の表示開始は変わらない
- 投稿の一覧・詳細で、つながった予定がある投稿だけ `schedule` が入る。一覧の予定の問い合わせは 1 回
- オフで保存すると投稿が消える。予定を消すと投稿が消える
- 本人が投稿を消したあと、オンで保存し直すと作り直す
- お知らせ時刻が終了以降、ひとことが長すぎると INVALID_ARGUMENT

frontend（vitest、`tsc --noEmit`）:

- シートの切り替え・時刻・ひとことが保存する値に入る。オフなら `announce` が false
- 投稿カードに出勤のカードが出る（`schedule` があるときだけ）。本文が空ならひとことの段を出さない
- 親投稿のプレビューで、本文が空なら出勤の 1 行

ローカルの実機:

- お知らせありで予定を入れると、本人のプロフィールに「予約」で出て、お知らせ時刻を過ぎるとフォロワーのタイムラインに出る
- 時間を変えるとカードの時間が変わり、予定を消すと投稿も消える
