# Dystopia profile screens design

## Context

[Issue #1517](https://github.com/panicboat/monorepo/issues/1517)「画面デザインの変更」への対応の第 4 段のうち、プロフィールまわり（4b）。第 4 段の分け方は [post screens の spec](2026-10-16-dystopia-post-screens-design.md) を参照（4a 投稿 → 4b プロフィール → 4c その他 → 4d 旧カルテ表の削除）。

第 1 段の spec は、プロフィール編集モーダル（`EditProfileModal`・`ProfileManager`）のシートへの載せ替えを第 4 段に回している。モックはプロフィールの上部、タブ、出勤、レビューの形を定めている。

### Decisions taken before this spec

| 論点 | 決定 | 理由 |
|---|---|---|
| プロフィールのタブ | 今のタブを残し、出勤をタブにする。モックの並び（キャストは投稿・出勤・レビュー、ゲストは投稿・カルテ）を先頭に置き、返信・メディア・いいねを後ろに続ける | モックの並びに合わせつつ、今ある機能を消さない |
| 出勤の編集 | モックどおり「まとめて編集」のシートにする。保存は今の API を日ごとに呼ぶ | 1 日ずつの入力の手間を減らす。バックエンドは変えない |
| レビュー | カルテと同じく、カードは要約だけにし、操作は詳細シートに置く | 第 3 段のカルテと同じ作りに揃える |

### Constraints

- バックエンドとの連携を壊さない。`src/app/api`・`src/stub`・`proto`・`dystopia/monolith` を変更しない。API を呼ぶ箇所のリクエスト内容も変更しない
- モックにしかない機能は追加しない。現行にしかない機能は削除しない
- 作成ボタンの花形メニューとモバイルの FAB は変更しない
- シートは第 1 段の `SideSheet` を使う。シートの中からの移動は第 1 段の規則（`router.replace`、今のページなら閉じるだけ）に従う

## Goals

- プロフィールの上部とタブをモックの形にし、出勤をタブにする
- 出勤をまとめて編集するシートを作る
- プロフィール編集と人格の追加をシートにする
- レビューを要約のカードと詳細シートにし、プロフィールから相手を選び済みで書けるようにする
- 4a から持ち越した、同じパスでクエリだけ変わる移動で投稿詳細シートが閉じない点を直す

## Non-goals

- 4c（メッセージ・通知・足跡・ランキング・設定）と 4d の範囲。ただし人格の追加は設定の人格の管理（`ProfileManager`）にあるが、本段で扱う
- 人格の削除の確認ダイアログ（中央のダイアログのまま）
- 投稿カードの画像拡大（ライトボックス。閲覧用の表示でありシートにしない）
- 「休み」を予定のない日と区別して保存すること（バックエンドに状態がない）

## Design

### Profile header (`src/modules/profile/components/ProfileHeader.tsx`)

モックの順に並べる。

1. カバー画像（なければ帯の色）
2. アバター、表示名と `@username`、右に操作ボタン（本人は「プロフィール編集」、他人は今のフォロー・メッセージ・その他のボタン）
3. 自己紹介
4. チップ: 「キャスト」または「ゲスト」、エリア（都道府県。未設定なら出さない）
5. 今ある項目（年齢・体型・業種・サイト・SNS など）は、チップの下に今の表示のまま残す

キャストのプロフィールで、出勤タブ以外を選んでいるときは、上部とタブの間に「今週の出勤」を出す。今日から 7 日のうち予定のある日を「10/13 20:00〜02:00」の形で並べ（なければ「今週の出勤予定はありません」）、「もっと見る →」で出勤タブに切り替える。

### Tabs (`src/modules/post/components/ProfileContentTabs.tsx`, `src/app/u/[username]/page.tsx`)

| プロフィール | タブの並び |
|---|---|
| キャスト | 投稿・出勤・レビュー・返信・メディア・いいね |
| ゲスト | 投稿・カルテ（キャストが見たときだけ）・返信・メディア・いいね・レビュー |

タブを切り替えたら、中身を `useEnterAnimation` でフェードさせる（鍵は選んでいるタブ）。今タブの上にある出勤の欄（`ScheduleSection`）は、出勤タブの中身に移す。

### Schedule tab (`src/modules/schedule/components/ScheduleTab.tsx`)

今日から 7 日を日ごとに並べる。各日は「10/13」と、時間帯（「20:00」「〜02:00」）か「未設定」。下に「出勤情報は予約可能枠を保証するものではありません。」を出す。本人には「まとめて編集」を出し、シートを開く。

### Schedule bulk sheet (`src/modules/schedule/components/ScheduleBulkSheet.tsx`)

見出しは「出勤予定をまとめて編集」。上から次を出す。

1. 「SHIFT / 2週間まとめて編集」と「日付を複数選択して、同じ時間帯を一括で設定できます。1日ずつ入力する必要はありません。」
2. 今日から 14 日の日付のボタン。押すたびに選ぶ・外すが切り替わる（`aria-pressed`）。各日に今の予定（時間帯か「未設定」）を出す
3. 「選択した日：N日」と「平日を選択」（14 日のうち月〜金をすべて選ぶ）
4. 「出勤」「予定を消す」の 2 つのボタン（どちらか一方を選ぶ）
5. 「出勤」のとき: 開始・終了の時刻（今の `TimeSelect`）と、プリセット「20:00〜02:00」「18:00〜23:00」「21:00〜03:00」（押すと開始・終了に入る）
6. 「選択した日に反映」: 選んだ日ごとに、「出勤」なら今の保存（`useSaveSchedule`）、「予定を消す」なら今の削除（`useDeleteSchedule`）を順に呼ぶ。日を選んでいないとき、「出勤」で開始か終了が空のときは押せない

すべて成功したら、トースト「出勤予定を更新しました」を出してシートを閉じる。一部が失敗したら、シートを開いたまま「保存できなかった日があります: 10/14, 10/16」を出し、失敗した日だけを選んだ状態にする。予定を取り直すのは、どちらの場合も行う。

### Profile edit sheet (`src/modules/profile/components/EditProfileSheet.tsx`)

`EditProfileModal` を `SideSheet` に載せ替え、`EditProfileSheet` とする（`EditProfileModal` は削除する）。見出しは「プロフィールを編集」。先頭に小さなカード「○○として編集中」と `@username` を出す。項目・検証・保存の処理は今のまま。

### Add profile sheet (`src/modules/profile/components/AddProfileSheet.tsx`)

`ProfileManager` の「追加」を、その場のフォームから「プロフィールを追加」シートに替える。先頭に「別の活動名で使うプロフィールを追加できます。」を出す。入力欄と保存の処理は今のまま。人格の削除の確認は今の中央ダイアログのまま。

### Review card and detail sheet

`ReviewEntryCard` を要約のカードと詳細シートに分ける。

カード（`src/modules/review/components/ReviewCard.tsx`）:

1. 小見出し「REVIEW / ゲストからキャストへ」
2. 書いた人のアイコン・表示名と相対時刻
3. 押せる枠（押すと詳細シートを開く）: キャストの名前と `@username`、右端に「★ 4.0」、本文（2 行まで）、チップ「ゲストによるレビュー」、書かれた人から見て非表示中なら「非表示中」
4. 枠の外に「キャストのプロフィールを見る →」（キャストのプロフィールの中では出さない）

詳細シート（`src/modules/review/components/ReviewDetailSheet.tsx`）: 見出し「レビューの詳細」。「REVIEW / ゲストからキャスト」、書いた人と「○○へのレビュー · 時刻」、大きな星、本文、編集済みの表示。今の操作をここに置く: 書いた人には編集（今の `EntryEditForm`）と削除、書かれた人には非表示・再表示。開いているレビューは一覧ごとに持つ（カルテと同じ）。操作のあとは、レビューの一覧を取り直し、シートには取り直した一覧の同じレビューを出す。操作が成功したらトーストを出す（編集「レビューを更新しました」、削除「レビューを削除しました」、非表示「レビューを非表示にしました」、再表示「レビューを表示に戻しました」）。削除したらシートを閉じる。

キャストのプロフィールのレビュータブで、ゲストが見ているときは、一番下に「レビューを書く」を出し、相手を選び済みの作成シート（`ComposeToSheet` の `initialTarget`）を開く。

### Follow lists (`ProfileFollowListPage`)

変えない。今の行（アバター、表示名、`@username`、フォローボタン、行全体がプロフィールへのリンク）はモックの形と同じである。モックの「@username · エリア」のエリアは、フォロー一覧の API が返さないため出せない（API を変えない制約）。モックの「→」は、行全体がリンクのため要らない。

### Post sheet: same path, different query

`PostDetailSheet` の中からの移動で、行き先のパスが今と同じでクエリだけ違うときは、`router.replace` のあとにシートを閉じる（`SideSheet` はパスが変わったときにしか閉じないため）。

### Undefined classes

レビュー（`ReviewComposer`・`ReviewsTab`・`ReviewEntryCard` を置き換える部品）・`IdentityLink`・`EntryEditForm` の `text-muted-foreground` などの定義のないクラスを、定義のあるトークン（`text-text-secondary` など）に替える。

## Testing

vitest:

- プロフィールの上部: チップ、本人と他人のボタン、今週の出勤の要約と「もっと見る →」で出勤タブに切り替わる
- タブ: キャストとゲストの並び、フェードの鍵
- 出勤タブ: 7 日の表示、本人だけに「まとめて編集」
- まとめて編集: 日の選び外し、平日を選択、プリセット、反映で日ごとに保存・削除が呼ばれる、押せない条件、すべて成功でトーストと閉じる、一部失敗で失敗した日を示して選んだまま残る
- プロフィール編集シート: 見出しと「○○として編集中」、保存の処理が呼ばれる
- 人格の追加シート: 開いて追加できる
- レビュー: カードの要約、押すと詳細シート、書いた人と書かれた人の操作、プロフィールの「レビューを書く」
- 投稿詳細シート: 同じパスでクエリだけ違うリンクで、replace のあとに閉じる

実機（使い捨て DB、puppeteer）: キャストのプロフィールでタブの並びと今週の出勤、出勤タブからまとめて編集で 3 日を反映、プロフィール編集シートで自己紹介を保存、ゲストでキャストのプロフィールからレビューを書き、カードから詳細を開く、書いた人が編集・削除、キャストが非表示、設定から人格を追加、検索ページの上の投稿詳細シートでハッシュタグを押すとシートが閉じる。
