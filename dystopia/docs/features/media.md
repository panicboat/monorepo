# メディア

画像と動画のアップロード、配信、削除を扱う機能。投稿の画像・動画、プロフィールのアバターとカバー画像に使う。キャストとゲストの両方が使う。

## Rules

| 操作 | 必要な状態 | 結果 |
|---|---|---|
| アップロード URL の発行 | 有効なプロフィールを使っている | ファイル名または種別が空なら拒否 |
| アップロード後の登録 | 有効なプロフィールを使っている | 次のどれかに当たれば拒否（400）。キーがそのプロフィール向けに発行されたものでない。サムネイルのキーがそのプロフィールのものでない。ファイルがアップロードされていない（失敗） |
| メディアの取得（ID 指定・一覧） | ログイン済みのアカウント（プロフィールは不要） | 配信 URL を含むメディアを返す。存在しない ID は含まれない（一覧）、または 404（単体） |
| メディアの削除 | 有効なプロフィールを使っている | アップロードしたプロフィールだけが削除できる。他人のメディアは削除されず、エラーにもならない（削除されたかどうかだけを返す） |
| アバター・カバー画像の設定 | 有効なプロフィールを使っている | 指定したメディア ID が本人のものかは確認しない |

- 種別は画像（`image`）と動画（`video`）の 2 つ。画面は、ファイルの MIME 種別が `video/` で始まれば動画、それ以外は画像として送る。サーバーは送られた種別を保存し、画像・動画以外の値は不明（`unknown`）として扱う。
- ファイルサイズの上限は、サーバーにも画面にもない。
- 投稿の画像は、GIF と SVG 以外なら画面でリサイズしてから送る。本体は長辺 2048 px・JPEG、サムネイルは長辺 640 px・JPEG。リサイズに失敗した場合は元のファイルを送る。GIF・SVG・動画は元のファイルを送る。
- プロフィール画像（アバター・カバー）はリサイズせず、元のファイルを送る。
- 配信 URL は保存されず、取得のたびに作られる。有効期限は 2 時間。署名は毎時の境界時刻で行うため、同じ時間帯の中では URL が変わらず、ブラウザのキャッシュが効く。

## Lifecycle

- 発行: 署名付きのアップロード URL を発行する。有効期限は 5 分。オブジェクトのキーは `media/<プロフィール ID>/<メディア ID>` の形で、拡張子は小文字にし、英数字 10 文字以下のものだけを付ける。キーに入るのはプロフィール ID で、アカウント ID は入らない。
- アップロード: 画面が発行された URL にファイルを PUT する。PUT が失敗すると登録は行われない。
- 登録: オブジェクトに所有アカウント ID のタグを付けてから、メディアの行を作る。タグを付けられなければ（オブジェクトが存在しなければ）行は作られず、登録は失敗する。
- 所有プロフィールの削除: そのプロフィールがアップロードしたメディアの行を消す。オブジェクトは消さないため、ファイルは残る。アカウントの削除でも同じ（[プロフィール](profiles.md)、[アカウント](account.md)）。
- 利用者による削除: 行とオブジェクト（本体とサムネイル）の両方を消す。
- 発行だけで登録しなかったオブジェクトは、行を持たず、アプリケーションからは参照できない。削除もされない。

## Interactions

- アバターとカバー画像は、プロフィールに保存されたメディア ID で参照する。要約表示のアバターはこのメディアの配信 URL（[プロフィール](profiles.md)）。
- 投稿の画像・動画は投稿に紐づく（[投稿](posts.md)）。
- 配信 URL は、投稿の閲覧条件とは別に、ログイン済みのアカウントなら取得できる。投稿を見られない利用者でも、メディア ID を知っていれば配信 URL を取得できる。

## Data

- `media.files`: メディアの行。種別、キー（本体・サムネイル）、所有プロフィール、所有アカウント、ファイル名、サイズ。

## Rationale

- キーに所有アカウント ID を入れない。キーは配信 URL に含まれるため、アカウント ID を入れると同じアカウントのプロフィール同士が URL から結びつくため。
- 所有アカウント ID はオブジェクトのタグに付ける。タグは行が消えた後も残るため、行より先に付け、タグを付けられないオブジェクトは登録しない。
