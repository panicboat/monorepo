# メディア

画像と動画のアップロード、配信、削除を扱う機能。
投稿の画像・動画、クチコミの出来事の添付、プロフィールのアバターとカバー画像に使う。
キャストとゲストの両方が使う。

## Rules

| 操作 | 必要な状態 | 結果 |
|---|---|---|
| アップロード URL の発行 | 有効なプロフィールを使っている | ファイル名が空か、MIME 種別が `image/` または `video/` で始まらなければ拒否する（400） |
| アップロード後の登録 | 有効なプロフィールを使っている | 次のどれかに当たれば拒否する。<br>キーがそのプロフィール向けに発行されたものでない（400）。<br>サムネイルのキーがそのプロフィールのものでない（400）。<br>ファイルがアップロードされていない（422） |
| メディアの削除 | 有効なプロフィールを使っている | アップロードしたプロフィールだけが削除できる。<br>他人のメディアは削除されず、エラーにもならない（削除されたかどうかだけを返す） |
| アバター・カバー画像の設定 | 有効なプロフィールを使っている | 使っているプロフィールがアップロードしたメディアでなければ拒否する（400）。<br>メディア ID を空にして送っても、設定済みの画像は外れない |

- 種別は画像（`image`）と動画（`video`）の 2 つ。
  - 画面は、ファイルの MIME 種別が `video/` で始まれば動画、それ以外は画像として送る。
  - サーバーは送られた種別を保存し、画像・動画以外の値は不明（`unknown`）として扱う。
- ファイルサイズの上限は、サーバーにも画面にもない。
- 投稿の画像は、GIF と SVG 以外なら画面で JPEG に描き直してから送る。
  - 本体は長辺 2048 px、サムネイルは長辺 640 px まで縮める。
  - 撮影場所や機種などのメタデータは送られない。
    - 描き直すため。
  - 読み込めない画像は送らず、「画像を読み込めませんでした。別の画像を選んでください」と表示する。
  - GIF と SVG は元のファイルを送る。
- 投稿の動画は、MP4・MOV・M4V・3GP（`video/mp4`・`video/quicktime`・`video/x-m4v`・`video/3gpp`・`video/3gpp2`）なら、`moov` と各 `trak` の直下にある `udta`・`meta` ボックスの種類を `free` に書き換えてから送る。
  - 撮影場所や機種などのメタデータはここに入る。
  - ボックスを消すとチャンクの位置（`stco`・`co64`）がずれるため、大きさは変えない。
  - 別のトラックなど、ほかの場所に記録されたデータは残る。
  - `moov` が見つからないなど読めない動画は送らず、「動画を読み込めませんでした。別の動画を選んでください」と表示する。
  - それ以外の形式の動画は元のファイルを送る。
- 動画は、送るときにサムネイルを作って本体と別に送る（クチコミの出来事の動画も同じ）。
  - 10 秒の位置のコマを、長辺 640 px の JPEG に描く。
    - 10 秒より短い動画は、長さの半分の位置のコマを描く。
  - コマはメタデータの書き換え前の元のファイルから切り出す。
  - 何も描かれていないコマはサムネイルにせず、描けるまで描き直す。
    - Safari は、まだ読み込んでいないコマを描くと、何も描かれていない画像を返すことがあるため。
    - 打ち切りまでに描けなければ、切り出せなかったものとして扱う。
  - 切り出せない、またはサムネイルを送れないときは、サムネイル無しで動画を送り、エラーは表示しない。
  - 切り出しは一度に 1 本ずつ行う。
    - 複数の動画を同時に読み込むと、iPhone ではメモリが足りなくなることがあるため。
- 再生前の動画は、サムネイルがあれば表紙にし、再生を押すまで動画を読み込まない。
  - サムネイルの無い動画は、0.1 秒の位置のコマを表示する。
- プロフィール画像（アバター・カバー）は、GIF と SVG 以外なら長辺 2048 px まで縮めた JPEG に描き直してから送る。
  - サムネイルは作らない。
  - 読み込めない画像は、投稿の画像と同じく送らない。
  - GIF と SVG は元のファイルを送る。
- メディアを ID で取得する API はない。
  - 配信 URL は、投稿・コメント・クチコミの出来事・プロフィールを返すときに、その閲覧条件を通ったものにだけ付く。
- 投稿・コメントへの添付は、使っているプロフィールがアップロードしたメディアだけを受け付ける（[投稿](posts.md)）。
- クチコミの出来事への新しい添付は、クチコミを書いたプロフィールがアップロードしたメディアだけを受け付ける。
  - その出来事にすでに付いているメディアは、同じアカウントの別プロフィールが編集で送り直しても受け付ける（[クチコミ](reviews.md)）。
- 配信 URL は保存されず、取得のたびに作られる。
  - 有効期限は署名時刻から 2 時間。
    - 署名時刻は毎時の境界時刻のため、取得から失効までは 1 時間を超え 2 時間以下になる。
  - 署名は毎時の境界時刻で行うため、同じ時間帯の中では URL が変わらず、ブラウザのキャッシュが効く。
  - 一度渡した配信 URL は、フォローの解除やブロックで投稿を見られなくなった後も、有効期限までは使える。

## Lifecycle

- 発行: 署名付きのアップロード URL を発行する。
  - 有効期限は 5 分。
  - オブジェクトのキーは `media/<プロフィール ID>/<メディア ID>` の形で、拡張子は小文字にし、英数字 10 文字以下のものだけを付ける。
  - キーに入るのはプロフィール ID で、アカウント ID は入らない。
- アップロード: 画面が発行された URL にファイルを PUT する。
  - PUT が失敗すると登録は行われない。
- 登録: 本体のオブジェクトに所有アカウント ID のタグを付けてから、メディアの行を作る。
  - タグを付けられなければ（本体のオブジェクトが存在しなければ）行は作られず、登録は失敗する。
  - サムネイルのオブジェクトには、タグを付けず、存在も確認しない。
- 所有プロフィールの削除: キーが `media/<プロフィール ID>/` で始まるオブジェクトと、そのプロフィールがアップロードしたメディアの行にあるオブジェクト（本体とサムネイル）を消してから、行を消す。
  - 行のない、登録しなかったオブジェクトも消える。
  - 1 つでも消せなければ、行を残して失敗する。
  - 次に削除するときに同じオブジェクトを消し直せる。
    - 行が残るため。
  - アカウントの削除処理でも同じ（[プロフィール](profiles.md)、[アカウント](account.md)）。
- 利用者による削除: オブジェクト（本体とサムネイル）を消してから、行を消す。
  - オブジェクトを 1 つでも消せなければ、行を残して「削除されていない」と返す。
    - 利用者がもう一度削除でき、所有プロフィールの削除でも行からオブジェクトを消し直せるため。
  - 削除したメディアを指す参照（アバター・カバー画像の ID、投稿・コメントの添付）は消えない。
    - 参照先の配信 URL は空になる。
  - クチコミの出来事の添付は、削除したメディアを指す行が消えず、その添付を返さなくなる。
- 投稿・コメントの削除: 添付していたメディアのうち、ほかの投稿・コメントの添付にも、クチコミの出来事の添付にも、アバター・カバー画像にも使われていないものの、オブジェクト（本体とサムネイル）と行を消す。
  - 投稿の削除では、その投稿に付いたコメントと返信の添付も対象になる。
  - オブジェクトを消せなかったメディアは、行を残す。
    - 所有プロフィールの削除で、行からオブジェクトを消し直せるため。
- クチコミの出来事の削除、出来事の編集で外れた添付、クチコミの削除（最後の出来事の削除を含む）: 外れたメディアのうち、投稿・コメントの添付にも、残っているクチコミの出来事の添付にも、アバター・カバー画像にも使われていないものの、オブジェクト（本体とサムネイル）と行を消す。
  - オブジェクトを消せなかったメディアは、投稿・コメントの削除と同じく行を残す。
- 発行だけで登録しなかったオブジェクトは、行を持たず、アプリケーションからは参照できない。
  - 所有プロフィールを削除する（アカウントの削除処理を含む）まで残る。
- アバターとカバー画像を変更すると、前の画像のメディアの行とファイルは残る。
  - そのプロフィールの削除、またはアカウントの削除処理で消える。
- 画面には、アップロード済みのメディアを個別に削除する操作がない。
  - `DELETE /api/media/{id}` は API にだけあり、画面からは呼ばれない。

## Interactions

- アバターとカバー画像は、プロフィールに保存されたメディア ID で参照する。
  - 要約表示のアバターはこのメディアの配信 URL（[プロフィール](profiles.md)）。
- 投稿の画像・動画は投稿に紐づく（[投稿](posts.md)）。
- クチコミの画像・動画は出来事に紐づく（[クチコミ](reviews.md)）。
- 投稿やコメントを削除すると、ほかで使われていない添付のメディアの行とファイルも消える。
- クチコミの出来事やクチコミを削除する、または出来事の添付を外すと、ほかで使われていない添付のメディアの行とファイルも消える。
- 配信 URL は、投稿・コメント・クチコミの出来事・プロフィールの閲覧条件を通った利用者にだけ渡る。

## Data

- `media.files`: メディアの行。
  - 種別、キー（本体・サムネイル）、所有プロフィール、所有アカウント、ファイル名、MIME 種別、サイズ。

## Rationale

- メディアを ID で取得する API を置かない。
  - ID で取れると、投稿の閲覧条件の外から、一度知った ID で画像・動画に届くため。
- 配信 URL の有効期限を、閲覧条件の変化に合わせて短くしない。
  - 短くするとキャッシュが効かず取得が増え、アプリを通す配信は費用と応答サイズの上限が合わないため。
- 削除で消すメディアから、ほかで使われているものを除く。
  - 同じプロフィールが同じメディアを複数の場所に付けられ、消すとほかの場所の画像が壊れるため。
- キーに所有アカウント ID を入れない。
  - アカウント ID を入れると同じアカウントのプロフィール同士が URL から結びつく。
    - キーは配信 URL に含まれるため。
- 所有アカウント ID はオブジェクトのタグに付ける。
  - タグは行が消えた後も残るため、行より先に付け、タグを付けられないオブジェクトは登録しない。
