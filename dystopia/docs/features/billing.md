# 課金

キャストとゲストのアカウントが、ロールごとの有料プランを Stripe で購読し、購読状態を管理するための機能。

**未稼働（本番環境から Stripe に到達できないため動かない）。**
以下はコード上の構成のみを記す。

## Rules

- 価格: アカウントのロールで決まる。
  - ゲストは専用の価格、キャストは専用の価格を使う。
  - ゲストとキャスト以外のロールは購読できない。
- 購読の保存: Stripe の購読ごとに 1 行を保存し、1 つのアカウントが複数の購読を持てる。
  - 解約した後にもう一度購読すると、解約済みの行を残したまま新しい行を保存する。
    - Stripe は再購読を新しい購読 id で作るため、解約済みの行を更新して使い回せない。
  - アカウントの現在の購読は、作成が最も新しい行。
    - 購読状態の取得は、現在の購読を返す。
    - 有効かどうかの判定は、アカウントの全行を見る。
- チェックアウト: 有効な購読（状態が trialing または active で、期間終了が現在より後）を 1 つでも持つアカウントは作成できない。
  - 期間末での解約を設定した購読も、期間が終わるまでは有効として扱う。
  - Stripe の顧客は初回だけ作成し、以後は再利用する。
  - 成功時と中断時の戻り先は設定値。
- カスタマーポータル: Stripe の顧客があるアカウントだけ作成できる。
  - 戻り先は設定値。
- ウェブフック: Stripe からの通知を受ける。
  - 署名がない、または検証に失敗すると 400 を返す。
  - 処理に失敗すると 500 を返し、Stripe に再送させる。
  - 同じイベント id は、処理済みであれば 2 回目以降を無視する。
    - 処理に失敗したイベントは、Stripe から再送されると処理し直す。
- 購読状態の同期: 購読の作成・更新で状態と期間終了を保存する。
  - 削除されたら canceled にする。
  - 一度 canceled になった購読は、後から届いた更新イベントで戻らない。
  - チェックアウト完了と、試用期間の終了が近いことの通知は処理しない。
  - 購読の通知で、Stripe の顧客に対応する行がなく保存できないものは、保存せずに処理済みにする。
    - 削除処理は顧客の行を消すため、削除後に届く通知がこれに当たる。
    - 失敗として扱うと、Stripe が再送し続けるため。
- 照合: 顧客ごとに保存済みの購読と Stripe の状態を比べ、状態・期間終了・期間末での解約予定に差があれば保存済みの状態を更新する。
  - 比べる購読は、canceled でないものすべてと、最も新しいもの。
  - 実行は手動の rake タスク（`billing:reconcile`）だけで、定期実行の設定はない。
  - Stripe 側に該当する購読がない場合は、保存済みの状態を変えない。
- 退会時の解約: アカウントの退会で、canceled でない購読のすべてを Stripe で期間末での解約に設定する。
  - 退会したアカウントに課金し続けないため。
  - 期間の途中では止めず、返金もしない。
  - 設定した購読には、期間末での解約予定を保存する。
  - 購読がないアカウントでは Stripe を呼ばない。
  - 退会中のアカウントへの退会の要求では、Stripe を呼ばない。
  - Stripe の呼び出しが 1 つでも失敗すると、退会が失敗してアカウントは有効のまま残る。
    - 期間末での解約を設定済みの購読は、設定が残る。
    - 退会日時の記録より先に設定するのは、失敗したときに退会をやり直せるようにするため。
  - 復活しても、期間末での解約の設定は戻らない。
    - 戻すには、カスタマーポータルで取り消すか、期間が終わった後にもう一度購読する。
- 削除処理: アカウントの削除処理で、Stripe の顧客と、購読と顧客の行を消す。
  - 顧客の行があるアカウントは、Stripe の顧客を削除してから、購読の行と顧客の行を消す。
    - 顧客を削除すると、Stripe に残っている購読はその場で終了する。
    - Stripe を先に呼ぶのは、失敗したときに顧客の行を残し、やり直しで同じ顧客を見つけられるようにするため。
    - Stripe に顧客がすでにないときは、削除済みとして続ける。
  - 顧客の行がないアカウントは、Stripe を呼ばずに購読の行だけを消す。
  - 失敗すると、そのアカウントの削除処理はそこで止まり、翌日の実行でやり直す。
  - `billing.stripe_events` はアカウントに紐づかないため、消さない。
- フロントエンドに課金の画面と呼び出し口はない。

## Interactions

- ロールは [アカウント](account.md) のロールを使う。
- 退会で購読が期間末での解約になり、削除処理で Stripe の顧客と課金の行が消える（[アカウント](account.md)）。

## Data

- `billing.customers` — アカウントと Stripe の顧客 id の対応
- `billing.subscriptions` — Stripe の購読ごとの状態、価格、期間終了、解約日時
- `billing.stripe_events` — 受け取ったウェブフックイベントと処理結果
