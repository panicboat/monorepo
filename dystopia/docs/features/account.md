# アカウント

電話番号とパスワードで登録・ログインする、利用者の認証単位。
キャストとゲストの両方が使う。
登録時に選んだロール（キャストまたはゲスト）はアカウントに紐づき、登録後に変える手段はない。
アカウントは作成直後にはプロフィールを持たず、初回のプロフィール作成の後は 1 つ以上のプロフィールを持つ（[プロフィール](profiles.md)）。

## Rules

### 登録

| 条件 | 結果 |
|---|---|
| 登録を完了したアカウントの電話番号 | 409。<br>「この電話番号は既に登録されています」 |
| 登録を完了しなかった電話番号（確認コードを入力していない、または確認後にアカウントが作られなかった） | 残った登録を消して登録し直せる |
| パスワードが 12 文字未満、または大文字・小文字・数字・記号のいずれかを欠く | 登録できない |
| 認証コードが一致しない、または期限切れ | 400。<br>「認証コードが正しくありません」 |
| 認証コードを確認した後、アカウントの作成に失敗 | 電話番号は確認済みになるが、アカウントは作られない。<br>同じ電話番号でもう一度登録すると、残った登録を消して登録し直せる |

- 認証コードは SMS で送られる。
- 電話番号が Cognito に残っているときは、その登録に対応するアカウントがなければ、残った登録を消して、もう一度登録する。
  - 確認コードを入力したかどうかは見ない。
    - 確認後にアカウントが作られなかった登録も、登録をやり直したい電話番号だから。
- 登録画面は年齢確認モーダルの確認と、規約・プライバシーポリシーへの同意チェックを必須にする。
  - この 2 つはサーバーに送られず、記録されない。
- ロールは登録画面のロール選択で決まる。
  - URL に `role=cast` があればキャストが初期選択になり、それ以外はゲストが初期選択になる。
- サーバーは登録時に送られたロールを保存し、申告どおりかは確認しない。
  - ロールが未指定または不明な値の場合は、ゲストとして保存する。

### ログイン

| 条件 | 結果 |
|---|---|
| 電話番号とパスワードが一致し、アカウントがある | ログインする。<br>退会中のアカウントなら復活する |
| 電話番号が未登録、またはパスワードが不一致 | 401。<br>「電話番号または認証コードが正しくありません」（両者で同じ応答） |
| 認証は通るがアカウントがない | 401。<br>「電話番号または認証コードが正しくありません」。<br>認証で発行されたトークンを無効にし、cookie は設定しない |

- 電話番号とパスワードの認証要求が失敗した場合は、認証基盤に届かなかったときも含めて、電話番号が未登録またはパスワードが不一致のときと同じ応答（401）を返す。
- 復活したときは「お帰りなさい。アカウントは復活しました。」を表示する。

### パスワード再設定

- 電話番号に SMS でコードを送る。
  - 未登録の電話番号にも同じ応答を返し、登録の有無は分からない。
- 再設定するパスワードは登録時と同じ方針に従う。
- コードの不一致・期限切れは「認証コードが正しくありません」。

### ログイン維持

- アクセストークンの有効期間は 1 時間、リフレッシュトークンの有効期間は 30 日（Cognito の設定）。
- ブラウザに保存される cookie は、アクセストークンが 1 時間、リフレッシュトークンが 30 日。
- アクセストークンの更新は `/api/` 宛ての要求を受けたときだけ行う。
  - 残りの有効期間が 60 秒以下なら、リフレッシュトークンでアクセストークンを取得し直す。
  - ページ遷移だけでは更新されない。
  - `/api/identity/` 配下の要求（`/api/identity/me` を除く）では更新しない。
    - 認証の route は自分で cookie を設定するため、更新と競合させない。
- 更新のたびに cookie の有効期限は 30 日後へ延びるが、Cognito のリフレッシュトークンは発行から 30 日で失効し、延びない。
  - そのため最後に認証してから 30 日を過ぎると、次の要求で 401 になる。
    - 401 に伴ってログイン情報を消すのは、`/api/identity/me` が 401 を返したときだけである。
- 更新に失敗したときは要求をそのまま通し、API が 401 を返す。

### ロックアウト

- アプリケーションはログインの失敗回数を数えず、アカウントをロックしない。
- Cognito の advanced security は OFF。

### 退会

| 条件 | 結果 |
|---|---|
| 設定画面で退会を実行 | 解約されていない購読があれば、すべて Stripe で期間末での解約に設定する（[課金](billing.md)）。<br>アカウントに退会日時を記録する。<br>Cognito のグローバルサインアウトが成功すると、他の端末のリフレッシュトークンが無効になり、アクセストークンを取得し直せなくなる。<br>他の端末では、既に発行されたアクセストークンが、有効期限（最長 1 時間）まで有効なまま残る。<br>cookie は消える |
| 退会中（削除処理前） | 所有する全プロフィールが他人から見えなくなる（[プロフィール](profiles.md)）。<br>同じ電話番号でログインすると復活する（削除処理が済むまで）。<br>復活しても、購読の期間末での解約は戻らない（[課金](billing.md)） |
| 退会から 90 日を過ぎた | 次回の削除処理（下記）でアカウントとプロフィールが消える。<br>Stripe の顧客と課金の行も消える（[課金](billing.md)）。<br>カルテ、クチコミ、メッセージは残る（[カルテ](karte.md)、[クチコミ](reviews.md)、[メッセージ](messages.md)） |

- 退会中のアカウントに退会の要求が届いても、退会日時は変わらない。
  - 要求は成功し、削除処理の 90 日は最初の退会日時から数える。
  - Stripe の購読には触れない。
- Stripe への解約の設定が失敗すると、退会は失敗し、退会日時は記録されない。
  - アカウントは有効のまま残り、cookie も消えないため、もう一度退会を実行できる。
- Cognito のグローバルサインアウトが失敗しても、退会の記録と cookie の削除は行われる。
  - その場合、他の端末のリフレッシュトークンは有効なまま残る。
- 削除処理は毎日 04:00（日本時間）に実行する。
  - 失敗しても再試行せず、翌日の実行でやり直す。
- 削除処理は退会日時が「実行時刻の 90 日前より前」のアカウントを対象にする。
  - ちょうど 90 日の時点は対象外。
- 削除処理は 1 アカウントごとに次の順で消す。
  1. 所有するすべてのプロフィール（その中の投稿・コメント・いいね・メディアの行とファイルなど。消える範囲は [プロフィール](profiles.md) を参照）
  2. 通知の Web Push 購読
  3. 課金（Stripe の顧客と、購読と顧客の行。[課金](billing.md)）
  4. Cognito のユーザー
  5. アカウント
- どれかが失敗したアカウントは退会中のまま残り、次回の実行で最初からやり直す。
  - 他のアカウントの処理は続ける。
  - Cognito のユーザーを消す前に失敗した場合、次回の実行までに同じ電話番号でログインすると、退会は取り消される。
    - それまでに消えたプロフィールは戻らない。
    - 課金の削除が済んでいたときは、Stripe の顧客と購読も戻らない。
  - Cognito のユーザーを消した後に失敗した場合、ログインはできず、次回の実行で消える。
- 削除処理は、退会したアカウントを消した後に、登録を完了しなかった認証情報も消す。
  - 対象は、Cognito での作成が「実行時刻の 24 時間前より前」で、アカウントがないユーザーである。
    - ちょうど 24 時間の時点は対象外。
    - 確認コードを入力していないユーザーと、確認後にアカウントが作られなかったユーザーの両方が対象になる。
  - 消す直前に、Cognito のユーザーとアカウントの有無をもう一度確認する。
    - 一覧を取ってから消すまでの間に、登録が完了したり、登録し直されたりしたユーザーを消さないため。
  - 1 人の削除に失敗しても、他のユーザーの処理は続ける。
    - 失敗があった実行は、最後に失敗として報告する。
    - 失敗したユーザーは残り、翌日の実行で再び対象になる。
- 運営者は、退会日時を 90 日より前の日時にしてから削除処理を実行すると、猶予を待たずにそのアカウントを消せる。
  - 18 歳未満、または高校生と分かった利用者の削除（規約の「利用資格」の条）はこの方法で行う。
  - 手順は [dystopia/lambda](../../lambda/README.md) にある。

## Lifecycle

```mermaid
stateDiagram-v2
    [*] --> 確認待ち: 登録（SMS コードを送信）
    確認待ち --> 有効: 認証コードの確認とアカウント作成
    確認待ち --> [*]: 作成から 24 時間経過後の削除
    有効 --> 退会中: 退会
    退会中 --> 有効: ログイン（復活）
    退会中 --> [*]: 退会から 90 日経過後の削除
```

- 確認待ち: 電話番号とパスワードは登録済みだが、アカウントはまだない。
  - アカウントができるまでログインできない。
  - Cognito での作成から 24 時間を過ぎると、削除処理で消える。
- 有効: ログインでき、プロフィールを使える。
- 退会中: 他人から見えるプロフィールはなく、プロフィールを使う操作もできない。
  - ログインすると有効に戻る。

## Interactions

- 退会中のアカウントのプロフィールは、検索・投稿・一覧のどこにも表示されない（[プロフィール](profiles.md)、[検索](search.md)、[投稿](posts.md)）。
- 他の利用者の投稿のいいね数とコメント数、および他の利用者のプロフィールのフォロー中・フォロワー数には、削除処理が済むまで、退会したアカウントの分が含まれる（[投稿](posts.md)、[フォロー・ブロック](follows-and-blocks.md)）。
- 削除処理で通知の Web Push 購読が消える（[通知](notifications.md)）。
- 退会で購読が期間末での解約になり、削除処理で Stripe の顧客と課金の行が消える（[課金](billing.md)）。
- カルテとクチコミは削除処理の対象に含まれず、残る（[カルテ](karte.md)、[クチコミ](reviews.md)）。
- 退会したアカウントが送ったメッセージは、本文とスレッドが残り、送り主は表示されない（[メッセージ](messages.md)）。

## Data

- `identity.accounts`: アカウントと、登録時に決めたロール、退会日時。
- `notifications.push_subscriptions`: プロフィール × 端末の Web Push 購読。
  - アカウントの ID も持ち、削除処理で消える。
- `billing.customers`、`billing.subscriptions`: アカウントの Stripe の顧客と購読。
  - アカウントの ID を持ち、削除処理で消える。
- Cognito のユーザープール: 電話番号とパスワードの認証情報。
  - 削除処理で消える。
  - 登録を完了しなかった認証情報の削除は、[退会](#退会) の削除処理に従う。

## Rationale

- 退会は即時の削除ではなく 90 日の猶予を置く。
  - 猶予中はログインだけで復活できる。
  - 退会から短い期間でプロフィールが消えるとサービスの信頼性が下がり、積み上げたカルテも無駄になるため、猶予を長めに取る。
- 削除処理は失敗したアカウントを退会中のまま残す。
  - 途中で止まったアカウントが他人から見えない状態を保ち、次回の実行で消し直せるようにするため。
  - 削除が済むまではログインで退会を取り消せるため、Cognito のユーザーを消す前に止まり、その後ログインしたアカウントは消し直さない。
