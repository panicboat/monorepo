# 足跡

キャストとゲストが、プロフィールのページを開いたとき、そのプロフィールの持ち主に訪問を残す機能。
持ち主は訪問者の一覧と未読数を見られる。

## Rules

### 記録条件

訪問 1 回ごとに、次の表の上から順に判定する。

| 状況 | 記録 |
|---|---|
| 訪問者と訪問先が同じプロフィール | 記録しない |
| 訪問者と訪問先のどちらかが相手をブロックしている | 記録しない |
| 訪問者プロフィールの「他人のプロフィール訪問時に足跡を残す」が off | 記録しない（初期値は on） |
| 訪問先プロフィールが取得できない | 記録しない |
| 上記以外 | 記録する |

- 同じアカウントの別プロフィール間の訪問も記録する。
- 訪問先プロフィールの公開設定は記録条件に含まれない。
- 記録のきっかけは、操作中のプロフィールと異なるプロフィールのページを開くこと。
  - ページを開くたびに 1 回記録する。

### 重複

- 訪問者と訪問先の組につき 1 行。
  - 再訪すると同じ行の訪問回数を 1 増やし、最終訪問日時を現在時刻にする。
- 同じ訪問者の連続した訪問も 1 回ごとに数える。
  - 時間による間引きはない。

### 一覧

- 訪問先のプロフィールだけが見られる。
- 最終訪問日時の降順。
- 1 ページは既定 20 件、上限 50 件。
- 訪問者プロフィールが取得できない行の除外は取得後に行われる。
  - 除外で 1 ページの件数に足りないときは、続きを取得して埋める。
  - 次ページが存在するかの判定は除外の後の件数で決まる。
- 訪問者とのブロック（どちら向きでも）がある行は一覧から除く。
- 訪問者プロフィールが取得できない行は表示しない。
- 行は保持期間なしで残る。
  - 消えるのは、プロフィールを削除したときと、アカウントの削除処理（[アカウント](account.md)）で所有するプロフィールを消したときだけ。

### 未読数

- 未読は、最終訪問日時が既読時刻より後の行の数。
  - 訪問回数ではなく行の数で数える。
- 既読時刻がなければ（一度も足跡を開いていなければ）、すべての行が未読。
- 既読時刻ちょうどの訪問は既読扱い。
- 足跡ページを開くと、一覧を読み込んだ後に既読時刻を現在時刻に更新する。
  - 一覧は既読時刻で未読かどうかを決めるため、先に更新すると前回からの未読が既読として出る。
- 未読数は一覧に出る訪問だけを数え、一覧と一致する。
  - ブロック（どちら向きでも）がある訪問者の行は数えない。
  - 訪問者プロフィールが取得できない行（プロフィールの無効化、アカウントの退会中）は数えない。
- 未読数はサイドナビに表示し、30 秒ごとに再取得する。
  - 「足跡の未読バッジ」が off のときは表示しない（件数は計算される）。

## Lifecycle

- 記録 → 未読（行の作成または最終訪問日時の更新） → 足跡ページを開くと既読 → 再訪で未読に戻る。
- プロフィール削除で、そのプロフィールが訪問者または訪問先である行と既読時刻が消える。

## Interactions

- 通知: 足跡は通知を発火しない。
  - 未読バッジの表示切替と訪問の記録は、通知の設定画面にある。
  - 詳細は [通知](notifications.md)。
- フォロー・ブロック: ブロックは記録と一覧の両方に影響する。
  - 詳細は [フォロー・ブロック](follows-and-blocks.md)。
- プロフィール: プロフィールのページを開くことが記録のきっかけになる。
  - 削除時の扱いは [プロフィール](profiles.md)。

## Data

- `footprints.visits` — 訪問者と訪問先の組、最終訪問日時、訪問回数
- `footprints.read_states` — プロフィールごとの既読時刻
