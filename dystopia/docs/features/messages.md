# メッセージ

キャストとゲストが、表示中の [プロフィール](profiles.md) として別のプロフィールと 1 対 1 でやりとりする機能。
送信できる相手は送信条件で決まり、受信者は新着を画面の再取得で確認する。

## Rules

### 送信条件

判定は次の順で行い、最初に当てはまった時点で送信を止める。

1. 本文が空 → 送信不可
2. 送信先がスレッドで指定された場合、送信者がそのスレッドの参加者でなければ送信不可
3. 送信先が自分自身 → 送信不可
4. 送信先プロフィールが存在しない（削除済み・表示できない） → 送信不可
5. 送信者と相手のどちらか一方でもブロックしている → 送信不可
6. 送信者のアカウントのロールがキャスト → 送信可（フォロー関係は問わない）
7. 送信者のアカウントのロールがゲスト、または送信者のプロフィールを表示できない → 送信者から相手へのフォローが承認済みなら送信可、それ以外は送信不可（フォローが必要）

相手のロールは送信可否に影響しない。
本文の上限 5000 文字は画面の入力欄だけで検証し、サーバーは空かどうかしか検証しない。

### スレッド

| 項目 | 内容 |
|---|---|
| 単位 | 2 つのプロフィールの組につき 1 スレッド（組の作成は重複しない） |
| 作成 | 相手との会話を開始したとき（作成時に上の送信条件と同じ判定を行う）、または最初のメッセージを送信したとき |
| 作成直後 | メッセージ 0 件。<br>最終メッセージ日時は空で、一覧では最後に並ぶ |
| 閲覧・送信・既読 | スレッドの参加者だけ可能。<br>それ以外は拒否 |
| 相手がブロック状態 | 既存のメッセージとスレッドは閲覧できる。<br>送信だけ不可 |
| 相手プロフィールが取得できない | 詳細画面の送信制限は「相手が利用できない」になり、送信は不可 |

### 未読数

- 未読は、相手が送ったメッセージのうち、自分の既読位置より作成日時が後のものの数。
  - 既読位置がなければ相手の全メッセージ。
- 一覧上部の未読数は、参加している全スレッドの未読の合計。
- 既読位置は、スレッドを開いて相手の最新メッセージが表示されたときに、そのメッセージの id で更新される。
  - サーバーは指定された id がそのスレッドに属するかを検証せず、そのまま既読位置にする。

### 受信方式

- 受信は polling。
  - メッセージ一覧と未読数は 6 秒ごとに再取得する。
- スレッド一覧と未読数の再取得は `/messages` 配下でのみ動く。
- ストリーミング（サーバーからの持続的な配信）は存在しない。

## Lifecycle

- 未作成 → 開始またはメッセージ送信でスレッドが生まれる → メッセージ送信のたびに最終メッセージ日時が更新され、一覧の並びが変わる。
- 参加者のプロフィールを削除すると、そのプロフィールの既読状態は消え、送信したメッセージの送信者とスレッドの参加者は空になる。
  - メッセージ本文とスレッドは残る。

## Interactions

- 送信のたびに受信者へ Web Push を送る（種類は message、本文は冒頭 100 文字）。
  - アプリ内の通知一覧には残らない。
  - 詳細は [通知](notifications.md)。
- 送信条件はブロックとフォローの状態を都度参照する。
  - 詳細は [フォロー・ブロック](follows-and-blocks.md)。
- プロフィール削除時の扱いは [プロフィール](profiles.md) に従う。

## Data

- `messaging.threads` — 2 つのプロフィールの組と最終メッセージ日時
- `messaging.messages` — メッセージ本文と送信者
- `messaging.read_states` — プロフィールごとのスレッドの既読位置

## Rationale

- 受信は polling にする。
  - 持続的な配信は受信者に届かない。
    - 本番の関数 URL はレスポンスを終端まで返すため。
