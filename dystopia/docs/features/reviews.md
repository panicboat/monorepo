# クチコミ

ゲストがキャストについて書く評価と出来事の記録。
書けるのはゲストだけで、閲覧はキャスト・ゲストの両方ができる。
一覧に出るかどうかは、当事者の有効性、双方向ブロック、鍵で決まる。
書き手のゲストや対象のキャストがプロフィールの削除・無効化・退会をしても、クチコミは残る。

## Rules

### 作成

- 書けるのはゲストのアカウントだけ。
- 対象は有効なキャストのプロフィールに限る。
  - ゲストのプロフィール、無効化されたプロフィール、退会中のアカウントのプロフィール、存在しないプロフィールは拒否する。
- 同じアカウントのプロフィールは対象にできない。
- 作成時のブロック確認はない。
  - フォローしていなくても作成できる。
  - 対象キャストが鍵付きでも同じ。
    - 書いた本人は、自分のクチコミを自分の一覧と個別表示で見られる。

### 閲覧

「有効」は、プロフィールが無効化されておらず、アカウントが退会中でなく、削除・purge されていない状態を指す。
クチコミは当事者が有効でなくなっても消さず、有効でない側を名前を伏せて表示する。
「鍵を通れる」は [プロフィール](profiles.md) の規則に従い、閲覧者ごとに判定する。
場面ごとに出る条件は次の通り。

| 場面 | 出る条件 |
|---|---|
| 対象キャストのクチコミ一覧 | 対象キャストが有効で、閲覧者が対象キャストに到達でき、対象キャストの鍵を通れること。<br>書き手の状態は問わない。<br>書き手の鍵は条件にならない。<br>閲覧者が書き手をブロックしている、または書き手にブロックされているクチコミは外れる |
| ゲストの「書いたクチコミ」一覧 | ゲストが有効で、閲覧者がそのゲストに到達でき、ゲストの鍵を通れること。<br>対象キャストが有効なら、閲覧者が対象キャストにも到達でき、対象キャストの鍵も通れること。<br>対象キャストが有効でなければ、対象を伏せて出る。<br>閲覧者が対象キャストをブロックしている、または対象キャストにブロックされているクチコミは外れる |
| 最近のクチコミ（ホーム） | 対象キャストが有効で、閲覧者が対象キャストに到達でき、対象キャストの鍵を通れ、書き手と対象のどちらともブロック関係がないこと。<br>書き手の状態は問わない。<br>書き手の鍵は条件にならない |
| 個別表示（作者アカウント） | 常に開ける。<br>同じアカウントの別プロフィールで開く場合も同じ |
| 個別表示（対象キャスト本人） | 使用中のプロフィールが対象キャストで、対象キャストが有効なら開ける |
| 個別表示（その他の閲覧者） | 閲覧者が見られるいずれかの一覧（対象キャストのクチコミ一覧、ゲストの「書いたクチコミ」一覧、最近のクチコミ）に出るなら開ける。<br>出ないものは URL で直接開いても「見つからない」扱い |
| 自分のクチコミ一覧と件数 | 作者アカウントが書いたものすべて。<br>当事者の状態は問わない。<br>件数（総数・未評価数）は先頭ページだけで返る |

- 到達できるのは、有効なプロフィール。
  - 閲覧者との間にどちらの向きでもブロックがあれば、到達できない。
- 書き手のゲストの鍵は、対象キャストの一覧と最近のクチコミに出る条件にならない。
  - 条件にすると、対象キャストの一覧が減り、全クチコミで計算する平均と合わなくなるため。
  - 書き手の鍵は、書き手の名前を伏せるかどうかだけを決める（下の「鍵付きのゲストの名前」）。
- 対象キャスト本人（使用中のプロフィールが対象キャスト）は、自分へのクチコミの一覧を、ブロック関係と鍵に関係なく見られる。
  - 同じアカウントの別プロフィールを使っているときは本人にならず、閲覧者と同じく、対象キャストへの到達・ブロック関係・対象キャストの鍵の条件に従う。
- ゲスト本人（使用中のプロフィールが書き手）は、自分の「書いたクチコミ」一覧を、対象キャストへの到達・ブロック関係・対象キャストの鍵に関係なくすべて見られる。
  - 対象キャストが有効でないものも、対象を伏せて出る。
- 書き手と対象の両方が有効でない場合、クチコミは他人が見る一覧には出ない。
  - 作者アカウントの自分のクチコミ一覧と個別表示だけに残る。
- 有効でない当事者は、表示名・ユーザー名・アバター・プロフィールへのリンクを出さない。
  - 削除済み・無効化・退会中は区別しない。
  - 書き手の場合は、プロフィール ID も、作者アカウントと対象キャスト本人以外には返さない。
- 書き手のゲストは「（無効なゲスト）」、対象のキャストは「（無効なキャスト）」と表示する。
  - クチコミは書き手がゲスト、対象がキャストと決まっているため、役割で出し分ける。
- アバターは画像なしで、頭文字は「?」。
- 有効でない対象キャストのユーザー名（「@...」）の併記も出さない。
- 自分のクチコミ一覧で、使用中でないプロフィールで書いたものには「@ユーザー名 として記録」を付ける。
  - そのプロフィールが有効でなければ「（無効なゲスト）として記録」になる。
- 1 ページは既定 20 件、上限 50 件。
- 一覧に出ないクチコミは、取得した行から取り除かれる。
  - 取り除いて 1 ページの件数に足りないときは、続きの行を取得して埋める。
  - 続きの有無は、取り除いた後の件数で判定する。
- 鍵を通れない閲覧者には、対象キャストのクチコミ一覧と「書いたクチコミ」一覧は空になる。
- 出来事の添付は、そのクチコミが出る場面で、本文と一緒に返す。
  - 対象キャストが有効でないときは、作者アカウントにだけ返す。
    - 本文は対象を伏せて残るが、写真は名前を伏せても対象のキャストと分かるため。
    - 同じアカウントの別プロフィールを使っているときも同じ。
    - 作者アカウントには、自分で上げた写真を編集や削除のときに確かめられるよう返す。
  - ファイルが消えている添付は返さない。
    - 書き手のプロフィールの削除・purge でメディアのファイルは消えるが、クチコミの本文は残るため。

### 鍵付きのゲストの名前

書き手が鍵付きのゲストで、閲覧者が書き手の鍵を通れないときは、クチコミの本文と評価を見せて、書き手の名前だけを伏せる。
伏せる条件は、対象キャストの一覧・最近のクチコミ・個別表示で同じ。

- 名前が見えるのは、次のどれかに当てはまる閲覧者。
  - 書き手の鍵を通れる閲覧者。
  - 対象キャスト本人。
    - カルテを書くなどの自己防衛に必要なため。
  - 作者アカウント。
    - 同じアカウントの別プロフィールを使っているときも同じ。
- 伏せたクチコミは、書き手の表示名・ユーザー名・アバター・プロフィールへのリンク・プロフィール ID を返さない。
  - プロフィール ID が残ると、プロフィールを引いて書き手を特定できるため。
  - 本文（評価・段階・結果・タグ・補足・日付）は返す。
  - 添付も本文と同じく返す。
- 画面は書き手を「（非公開のゲスト）」と表示し、名前の押下でプロフィールへ移動しない。
  - 「（無効なゲスト）」とは別の表示にする。
    - 退会した人のクチコミに見えないようにするため。
- 書き手が有効でないときは、鍵付きでも「（無効なゲスト）」を優先する。
  - 有効でない書き手の鍵は判定しない。

### 評価と平均

- 評価は 1〜5 の整数。
  - 0 または未指定は未評価。
- 平均評価は、対象キャストへのクチコミのうち評価済みのものを書き手プロフィールごとに平均し、その平均の平均で求める。
  - 評価者数は評価した書き手プロフィールの数で、同じアカウントの複数プロフィールは別々に数える。
  - 未評価のクチコミは平均にも評価者数にも含まれない。
  - 評価済みクチコミ数には、未評価のクチコミは含まれない。
  - 評価済みのクチコミがない場合、平均評価・評価者数・評価済みクチコミ数は 0 になる。
- 平均を返すのは、対象キャストの鍵を通れる閲覧者だけ。
  - 通れる閲覧者には、閲覧者に関係なく同じ値を返す。
    - ブロック関係にある書き手の評価も含まれる。
    - 鍵付きのゲストの評価も含まれる。
  - 通れない閲覧者には、平均評価・評価者数・件数を 0 で返す。
    - ブロック関係にある閲覧者にも、鍵付きのキャストの平均は返さない。
    - 平均だけを見せると、隠したクチコミの評価が分かるため。
- 書き手の状態（無効化・退会中・削除・purge）にかかわらず、そのクチコミの評価は平均と評価者数に含まれる。
- 対象キャストが有効でない（無効化・退会中・削除済み）場合、一覧は空で、平均評価は 0、評価者数は 0、件数は 0 になる。

### 編集・評価・削除

- 作者アカウントだけが実行できる。
  - 同じアカウントの別プロフィールからも実行できる。
- 作者アカウントが退会中の場合を除き、当事者の状態は条件にしない。
  - 退会中は有効なプロフィールを使えず、ログインで有効に戻るまで編集・評価・削除できない。
  - 作者が有効なプロフィールを使っていれば、対象キャストや書き手のプロフィールが有効でなくても、自分のクチコミを編集・評価・削除できる。
  - 作者がいつでも自分のクチコミを削除できるようにするため。

### 添付

- 添付できるのは、段階が `service`（画面では「利用」）の出来事だけ。
  - 別の段階の出来事に添付を送ると拒否する（400）。
- 1 つの出来事に、画像と動画を合わせて 4 件まで。
  - 画面とサーバーの両方が検査する。
  - 4 件を超えると拒否する（400）。
- 同じメディアを 1 つの出来事に 2 回付けると拒否する（400）。
- 種別は画像（`image`）と動画（`video`）だけ。
  - それ以外の種別は拒否する（400）。
- 添付できるのは、使っているプロフィールがアップロードしたメディアだけ。
  - 使っているプロフィール以外がアップロードしたメディアを新しく付けると拒否する（400）。
  - 出来事の編集では、その出来事にすでに付いているメディアを、同じアカウントの別プロフィールで送り直せる。
    - 別のプロフィールで編集しても、付いている添付が外れないようにするため。
    - 新しく加えるメディアは、使っているプロフィールがアップロードしたものでなければならない。
- 添付は必須ではない。
- 添付を送れるのは、クチコミの作成（最初の出来事）、出来事の追加、出来事の編集の 3 つ。
- 出来事の編集は、添付の一覧を送られたもので置き換える。
  - 空の一覧を送ると、添付がすべて外れる。
- `service` の出来事を別の段階に編集するときは、添付を空で送る必要がある。
  - 画面は、段階を切り替えたときに添付を外す。
- 出来事の削除、編集で外れた添付、クチコミの削除（最後の出来事の削除を含む）で外れたメディアは、ほかで使われていなければファイルも消える（[メディア](media.md)）。

## Lifecycle

作成 → 出来事の追加・編集・削除、評価の設定 → 最後の出来事の削除で消滅、の順に状態が進む。
期限で閉じる状態はない。

- 作成: 初回の出来事が必須。
  - クチコミと出来事を同じ処理で保存する。
  - 活動日時は作成時刻になる。
- 出来事の追加: 作者だけが実行できる。
  - 活動日時を現在時刻にする。
  - 対象キャストの一覧は活動日時の降順なので、追加したクチコミが先頭に来る。
- 出来事の編集と評価の設定: 活動日時は変わらず、更新日時が変わる。
  - 出来事の日付を変えると、最終出来事日も変わることがある。
- 出来事の削除: 残りが 2 件以上あれば、その出来事だけを消す。
  - 残り 1 件の出来事を消すと、クチコミ全体が消える。
- 出来事の段階: `reservation`、`service`、`aftercare` の 3 つだけを受け付ける。
- 出来事の結果とタグ: 段階ごとに決まった値だけを受け付ける。
  - 同じタグは 1 出来事に 1 回だけ付けられる。
- 出来事の日付: 日本時間の今日以前、`YYYY-MM-DD` 形式だけを受け付ける。
  - 最終出来事日は出来事の日付の最大値に追従し、最近のクチコミ（ホーム）の並び順の基準になる。
  - 並びは最終出来事日、作成日時、IDの降順。
- 出来事の補足: 500 文字以下。
  - 空白だけの補足は保存されず、補足なしとして扱われる。
    - 半角・全角のスペース、タブ、改行など、Unicode の空白だけの補足が対象。
  - 補足が必須なのは、`reservation` の `cast_no_show`、`service` の `ended_early`、`aftercare` の `trouble_occurred`。
- 出来事は、出来事の日付の古い順に並ぶ。
  - 同じ日付の出来事は、作成順に並ぶ。
- アプリの操作では、クチコミの行が消えるのは、作者が削除したとき（最後の出来事を消したときを含む）だけ。
  - 運営者が利用規約に基づいて削除する場合は、この限りでない。
- プロフィールの削除・purge でクチコミは消えない。
  - 書いたものも、そのプロフィールについて書かれたものも残り、有効でない当事者は役割つきの伏せた名前で表示される。
  - 退会したアカウントが purge されたときも同じ。
- 対象キャストが有効でなくなると、そのキャストのクチコミ一覧は空になり、平均は 0 になり、最近のクチコミからも外れる。
  - 書き手のゲストが有効なら、「書いたクチコミ」一覧と個別表示には対象を伏せて残る。
  - 対象キャストが有効に戻ると、元どおり見える。
- 書き手のゲストが有効でなくなっても、対象キャストが有効なら、そのクチコミは書き手を伏せて対象キャストの一覧・最近のクチコミ・個別表示に残り、平均にも含まれる。
  - ゲストの「書いたクチコミ」一覧は出ない。
    - ゲストのページがないため。

## Interactions

- [プロフィール](profiles.md): プロフィールの削除でクチコミは消えない。
  - 無効化・削除・退会は、閲覧と平均の条件と、当事者の伏せた表示に効く。
  - 鍵は、閲覧と平均の条件と、鍵付きのゲストの伏せた表示に効く。
- [フォロー・ブロック](follows-and-blocks.md): 双方向ブロックは一覧と個別表示から除外する。
  - 作者アカウントの「自分のクチコミ一覧」と個別表示、書き手のゲスト本人の「書いたクチコミ」一覧、対象キャスト本人の「対象キャストのクチコミ一覧」と個別表示には、ブロックは効かない。
  - ブロックしても平均からは除外されない。
  - 書き手のプロフィールが削除・purge されるとブロックの行も消えるため、そのゲストをブロックしていた閲覧者にも、書き手を伏せたクチコミが見える。
  - 承認済みのフォロー関係は、鍵を通れるかの判定に使われる。
    - 承認待ちは承認済みとして扱わない。
- [アカウント](account.md): 退会後の purge でもクチコミは消えない。
- 画面:
  - ホームの「クチコミ」タブは全ロールに表示される。
  - 下部ナビの「クチコミ」はゲストだけに表示される。
  - キャストのプロフィールには「クチコミ」タブが表示され、対象キャストへのクチコミと平均を見られる。
    - 鍵を通れない閲覧者には、内容の代わりに「フォローすると見られます」と表示する。
    - ブロック関係にある閲覧者には、この案内を出さない。
      - フォローできない相手に案内しても意味がないため。
    - ゲストには、鍵付きのキャストでも「このキャストのクチコミを書く」を表示する。
  - ゲストのプロフィールには「クチコミ」タブが表示され、そのゲストが書いたクチコミを見られる。
    - 鍵を通れない閲覧者には、同じ案内を表示する。
  - クチコミの詳細は、出来事ごとに、補足の下へ添付を表示する。
  - 一覧のカードは、出来事の並びで最後にある添付付きの出来事の添付を、要約のボタンの下に表示する。
    - 最新の出来事に添付がなくても、写真がカードから消えないようにするため。
    - 大きさは投稿の画像・動画と同じ。
  - 出来事のフォームは、段階が「利用」のときだけ添付の欄を出す。

## Data

- `review.reviews`: クチコミ本体。
  - 作者アカウント、作者プロフィール、対象プロフィール、評価、最終出来事日、活動日時を持つ。
  - プロフィールの削除・purge のあとも行が残り、作者アカウントとプロフィールの ID は参照先がなくなっても残る。
- `review.events`: クチコミの出来事。
  - クチコミ削除に連動して消える。
- `review.event_media`: 出来事に添付した画像と動画。
  - 出来事の削除に連動して消える。
  - メディアを削除しても、そのメディアを指す添付の行は消えない。
    - 行が残った添付は返さない。
- `identity.accounts`: アカウントのロール。
  - ゲスト・キャストの判定と、退会の判定に使う。
- `profile.profiles`: 書き手と対象のプロフィールの有効性と鍵。
- `social.follows`: 鍵を通れるかの判定に使う承認済みのフォロー関係。
- `social.blocks`: 双方向ブロックの判定。

カラムの詳細は [data model](../data-model.md) を参照。
