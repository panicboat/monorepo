# 通知

キャストとゲストが、表示中のプロフィールに起きた反応（いいね・コメント・返信・メンション・フォロー・フォロー申請）を一覧で確認し、端末へ Web Push で新着を受け取る機能。
通知はプロフィール単位で届き、一覧も表示中のプロフィール宛てのものだけを表示する。

## Rules

### 通知の種類

| 種類 | 発火するとき | 受け取るプロフィール | 設定キー |
|---|---|---|---|
| いいね | 投稿に新たにいいねされたとき。<br>いいねを取り消して押し直すと再び発火する | 投稿の作成者 | like |
| コメント | 投稿にコメントが作成されたとき（返信は除く） | 投稿の作成者 | comment |
| 返信 | コメントに返信が作成されたとき | 返信先コメントの作成者 | reply |
| メンション | 新規作成された投稿のうち公開時刻が現在時刻以下のもの、またはコメントが作成されたとき。<br>本文でメンションされたプロフィールがその投稿を閲覧できる場合 | メンションされたプロフィール | mention |
| フォロー | 承認不要のプロフィールへのフォローが成立したとき | フォローされたプロフィール | follow |
| フォロー申請 | 承認が必要なプロフィールへのフォローが作成されたとき | フォローされたプロフィール | follow |
| メッセージ | メッセージを送信したとき。<br>アプリ内の通知一覧には残らず、Web Push のみ | 受信者 | message |

- 発火しない条件:
  - 受信者と発火者が同じプロフィール。
  - 受信者が発火者をブロックしている（逆向きのブロックは判定しない）。
- 発火処理が失敗しても、元の操作（いいね・コメント・フォローなど）は失敗しない。
- 集約: 同じ受信者・同じ種類・同じ対象の通知は 1 行にまとめ、件数・最新の発火者・最新の発火時刻を持つ。
  - 対象はいいねとコメントが投稿、返信が親コメント、メンションが投稿またはコメント、フォローとフォロー申請が発火元のプロフィール。

### 一覧

| 項目 | 内容 |
|---|---|
| 表示対象 | 表示中のプロフィール宛ての行。<br>最新の発火時刻の降順 |
| 1 ページ | 既定 20 件、上限 50 件 |
| 非表示になる行 | 最新の発火者のプロフィールが取得できない行 |
| 未読数 | 既読日時が空で、最新の発火者のプロフィールが取得できる行の数。<br>発火の件数ではなく行の数 |
| 未読数の再取得 | 30 秒ごと |

### 既読

- 未読の行をタップすると、その行を既読にする要求を送ってから遷移する。
  - 要求の完了は待たない。
  - 要求が失敗してもエラーは表示せず、遷移は止めない。
    - 失敗した行は未読のまま残る。
- 全件既読は一括で行う。
- 既読にできるのは表示中のプロフィール宛ての行だけ。
- 集約行に再度の発火があると既読日時は空に戻り、未読になる。

### 通知設定

- 設定はプロフィールごと。
  - 初期値は全項目 on。
- 種類別の設定は Web Push の送信だけを制御し、そのプロフィールのすべての端末に効く。
  - アプリ内の一覧は設定に関係なく記録される。
- 「この端末で受け取る」は、使用中のプロフィールがこの端末の購読を持っているかどうかで、設定値ではない。
  - プロフィールを切り替えると、切り替え先のプロフィールの状態を表示する。
- 足跡に関する 2 項目（未読バッジ・訪問の記録）も同じ設定に含まれる。
  - 詳細は [足跡](footprints.md)。

### 通知タップの開き先

Web Push の通知をタップすると、宛先プロフィールの状況に応じて開き先が決まる。

| 宛先プロフィールの状況 | プロフィールの切替え | 開き先 |
|---|---|---|
| 表示中のプロフィールと同じ | なし | 通知の宛先パス（宛先パスがアプリ外のときは通知一覧） |
| アカウントが操作できる別のプロフィール（無効化・拒否されていない） | 宛先プロフィールへ切替え | 通知の宛先パス（同上） |
| アカウントが操作できないプロフィール（無効化・拒否・アカウントに属さない） | なし | トップページ |
| 通知の記録が読めない | なし | 通知一覧 |

アプリ内の通知一覧からの遷移は、表示中のプロフィール宛ての行だけなので切替えを行わず、宛先パスへ直接遷移する。

### Web Push

購読はプロフィール × 端末（endpoint）で持つ。
端末で「この端末で受け取る」をオンにしたプロフィール宛ての通知だけが、その端末に届く。

- 登録: 「この端末で受け取る」をオンにすると、ブラウザで通知を許可して購読を作り（既にあれば使い回し）、使用中のプロフィールの購読として登録する。
  - 有効なプロフィールを使っている必要がある。
  - 購読先（endpoint）は https かつポート 443 で、既知の Push サービス（Google の FCM、Apple、Mozilla、Windows）のホストだけを受け付ける。
  - endpoint は 2048 文字以内。
  - 暗号鍵は base64url 形式で 256 文字以内。
    - 末尾の `=` は 2 個まで付いてよく、文字数には数えない。
  - 条件を満たさない登録は拒否する。
  - 同じ endpoint の、別のアカウントの購読は削除する。
  - 同じ endpoint の残りの購読の暗号鍵は、登録された鍵にそろえる。
- 端末の引き継ぎ: ログイン中のアカウントでアプリを開くと、同じ endpoint の、別のアカウントの購読を削除する。
  - 今のアカウントのプロフィールには、オンにするまで届かない。
    - 今のアカウントの購読は作らないため。
- 解除: 「この端末で受け取る」をオフにすると、使用中のプロフィールと endpoint が一致する購読だけを削除する。
  - ブラウザの購読は解除しない。
    - 同じ端末の他のプロフィールが使うため。
- 送信条件（すべて満たすとき送信する）:
  1. Web Push の鍵（VAPID）と連絡先（VAPID の subject）が設定されている。
     - 未設定のときは公開鍵が空になり、何も送らない。
  2. 受信者プロフィールのその種類の設定が on。
  3. 発火者と受信者の両方のプロフィールが取得できる。
  4. 受信者プロフィールに購読が 1 件以上ある。
- 送信先: 受信者プロフィールの購読だけ。
  - 同じアカウントの別プロフィールの購読には送らない。
- 内容:
  - タイトルは発火者の表示名。
    - 送り先の端末（endpoint）に、同じアカウントの表示可能なプロフィールの購読が 2 つ以上あるときは「発火者 → 受信者」。
    - 端末ごとに決める。
  - 本文は種類ごとの定型文に、本文の抜粋（100 文字まで）を続けたもの。
    - メッセージは抜粋のみ。
  - 遷移先は `/notifications/open` に受信者と遷移先パスを付けたもの。
- 優先度: メッセージは高、それ以外は通常。
- 有効期間は 1 日。
- 送信失敗:
  - 購読が無効または期限切れと Push サービスに判定されたとき、その endpoint の購読をプロフィールに関係なくすべて削除する。
  - タイムアウトやその他の失敗では購読を残し、再送しない。
  - 送信失敗で元の操作は失敗しない。
- 購読の削除: プロフィールの削除でそのプロフィールの購読を、アカウントの削除処理でそのアカウントの購読をすべて削除する。

## Lifecycle

- 発火 → 未読の行が作成されるか、既存の行の件数が増えて未読に戻る → 既読にすると既読日時が入る → 同じ集約キーで再発火すると件数が増えて未読に戻る。
- 受信者プロフィールを削除すると、その受信者としての行、通知設定、Web Push の購読が消える。
  - 発火者として最新の行も消える（その行に含まれる他の発火者は残らない）。
- 投稿を削除しても、その投稿に対する通知の行は消えない。
  - 行をタップすると、投稿は見つからない扱いになる。
- コメントの削除、いいねの取り消し、フォロー解除では、通知の行は消えない。
  - 行は一覧に残り、表示も変わらない。
- フォロー申請の通知は、拒否・取り下げ・承認の後も行が残る。

## Interactions

- 投稿: いいね・コメント・返信・メンションの発火元。
  - 詳細は [投稿](posts.md)。
- フォロー・ブロック: フォロー・フォロー申請の発火元、ブロックによる発火抑止。
  - 詳細は [フォロー・ブロック](follows-and-blocks.md)。
- メッセージ: 送信時に Web Push を送る。
  - 詳細は [メッセージ](messages.md)。
- 足跡: 足跡の未読バッジと訪問の記録は、この機能の設定画面で切り替える。
  - 詳細は [足跡](footprints.md)。
- プロフィール・アカウント: プロフィール削除でそのプロフィールの行・設定・購読が消え、アカウントの削除処理でそのアカウントの購読がすべて消える。
  - 詳細は [プロフィール](profiles.md)、[アカウント](account.md)。

## Data

- `notifications.notifications` — 集約された通知の行（件数・最新の発火者・既読日時）
- `notifications.preferences` — プロフィールごとの通知設定
- `notifications.push_subscriptions` — 端末の Web Push 購読（プロフィール × endpoint）

## Rationale

- 購読をプロフィール × 端末で持つ。
  - 端末ごとに通知を受け取るプロフィールを選べるようにするため（例: この端末では仕事用のプロフィールだけ受け取る）。
- 送信は発火処理の中で同期的に行い、購読ごとに TCP 接続・TLS 確立・読み取りの各待ちを 3 秒で打ち切る。
  - 書き込みの待ちは 3 秒で打ち切らず、HTTP クライアントの既定の 60 秒になる。
  - 送信の遅延は発火元の処理時間に上乗せされる。
- 中身を読めない Web Push も汎用の通知を表示する。
  - 表示されない通知が続くと、ブラウザが購読を無効化するため。
- 通知タップ時のプロフィール切替えは、端末側に保存された記録からだけ行う。
  - リンクを細工して、どのプロフィールが同じアカウントに属するかを推測させないため。
